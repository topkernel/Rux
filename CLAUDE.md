## ⚠️ Core Principle (Absolutely Must Not Be Violated)

### **Full POSIX/ABI Compatibility, No Innovation**

This is the **highest guiding principle** for Rux kernel development. All design and implementation decisions must adhere to this principle.

**Core Requirements**:
- **100% POSIX Compatible**: Full compliance with POSIX standards
- **Linux ABI Fully Compatible**: Binary compatible with Linux kernel ABI
- **System Call Compatible**: Use Linux system call numbers
- **Filesystem Compatible**: Support Linux filesystems (ext4, btrfs)
- **ELF Format Compatible**: Executable format identical to Linux

**Strictly Prohibited**:
- ❌ Never "optimize" Linux designs
- ❌ Never create new system calls
- ❌ Never change existing interface behaviors
- ❌ Never "reinvent the wheel"
- ❌ Never deviate from standards for "elegance"

**Implementation Approach**:
1. Directly reference Linux kernel source code
2. Use the same system call numbers
3. Use the same structure layouts
4. Use the same filesystem formats
5. Follow POSIX standards

> **Key**: Our goal is to rewrite the Linux kernel in Rust, not to create a new system. Any "innovation" that deviates from Linux standards is wrong.

**Reference Resources**:
- Linux kernel source: https://elixir.bootlin.com/linux/latest/source/
- Linux man pages (`man 2 syscall`)
- Linux kernel documentation: Documentation/
- POSIX standard: https://pubs.opengroup.org/onlinepubs/9699919799/

## Project Overview

**Rux** is a Linux-like operating system kernel entirely written in Rust.

### Core Features
- **Language**: Rust (no_std, except for necessary platform assembly)
- **Architecture**: **RISC-V only (riscv64)**
  - ✅ RISC-V 64-bit - Fully supported, current default architecture
  - ❌ ARM64 (aarch64) - Removed, not maintained
  - ❌ x86_64 - Not implemented
- **Goal**: Linux-compatible operating system kernel
- **Phase**: Phase 17 completed (RISC-V architecture fully implemented)

### Tech Stack
- **Build**: Cargo + custom build.rs
- **Configuration**: TOML + interactive menuconfig
- **Testing**: QEMU emulation + GDB debugging
- **Documentation**: Markdown + code comments


## Key Files

### Configuration Files
- **Kernel.toml** - Main kernel configuration (read at compile time)
- **Cargo.toml** - Rust workspace configuration
- **.cargo/config.toml** - Cargo toolchain configuration

### Auto-generated Files
- **kernel/src/config.rs** - Auto-generated by build.rs from Kernel.toml, do not edit manually

### Important Scripts
- **build/Makefile** - Detailed build commands
- **test/run.sh** - Quick kernel run script

## Common Development Tasks

### Compile and Run
```bash
# Build kernel
make build

# Build userspace programs
make user

# Build Rootfs
make rootfs

# Run kernel, never start with qemu command directly to avoid wrong parameters
make run  # Start default shell

# Run unit tests
make test
```

## Architecture-Specific Information

### riscv64 (Current Default and Only Supported)
- **Entry Point**: 0x80200000
- **Page Size**: 4096 bytes
- **Exception Level**: S-mode (kernel runs)
- **UART Base Address**: 0x10000000 (ns16550a)
- **Timer**: RISC-V architecture timer
- **Interrupt Controller**: PLIC (Platform-Level Interrupt Controller)

### Boot Process
1. **boot.S**: OpenSBI initialization, jump to kernel
2. **Set Stack**: Use sufficiently large stack space
3. **Zero BSS**: Clear uninitialized data
4. **Jump to _start**: Rust code entry
5. **Initialization**: UART → Exception → Timer → Interrupt

### Memory Layout
```
0x80200000  Kernel code segment
0x80210000  Kernel data segment
...          BSS segment, stack space, etc.
```

## Code Conventions

### Rust Code
- **no_std**: No standard library
- **Panic Policy**: Abort (hang)
- **Inline Assembly**: Use `core::arch::asm!`
- **Global Assembly**: Use `core::arch::global_asm!`

### Assembly Code
- **Syntax**: RISC-V (GNU as)
- **Alignment**: As needed
- **Comments**: Use C style (`//` or `/* */`)

### File Organization
- Each architecture has its own directory in `kernel/src/arch/*/`
- Drivers are organized by type under `kernel/src/drivers/`
- Use modular `mod.rs` to export public interfaces

## Configuration System

### Kernel.toml Parsing
1. `kernel/build.rs` reads `Kernel.toml` at compile time
2. Generates `kernel/src/config.rs` (containing constant definitions)
3. Kernel code uses configuration via `crate::config::*`

### Adding New Configuration Items
1. Add configuration item in `Kernel.toml`
2. Add parsing in `kernel/build.rs`'s `generate_config_code()`
3. Add corresponding constant in `kernel/src/config.rs`

## Troubleshooting

### Compilation Issues
- Check Rust version: `rustc --version`
- Clean build: `make clean`
- Check target toolchain: `ls ~/.rustup/toolchains`

### Runtime Issues
- Check QEMU version: `qemu-system-riscv64 --version`
- Check kernel compilation: `ls target/riscv64gc-unknown-none-elf/debug/rux`
- View output: Use `-serial mon:stdio` option

### Configuration Not Taking Effect
- Check if `kernel/src/config.rs` is updated
- Clean and rebuild: `make clean && make build`

## Development Guide Following "No Innovation" Principle

### When Adding New Features

**Must Do First**:
1. Check Linux kernel source for corresponding feature implementation
2. Read relevant Linux man pages
3. Check POSIX standard documentation
4. Confirm using the same interfaces and data structures

**Prohibited Behaviors**:
- ❌ Modify interfaces based on own "understanding"
- ❌ Change design for "simplicity"
- ❌ Update because "Linux design is too old"
- ❌ Create new abstractions or interfaces

### Specific Implementation Guidelines

#### System Calls
```rust
// ✅ Correct: Use Linux system call numbers
pub const __NR_read: usize = 63;   // Exactly matches Linux

// ❌ Wrong: Define your own system call numbers
pub const SYS_RUX_READ: usize = 1000;  // Absolutely prohibited!
```

#### Data Structures
```rust
// ✅ Correct: Reference Linux structures
#[repr(C)]
pub struct Stat {
    st_dev: u64,
    st_ino: u64,
    st_mode: u32,
    st_nlink: u32,
    st_uid: u32,
    st_gid: u32,
    st_rdev: u64,
    st_size: i64,
    st_blksize: u64,
    st_blocks: u64,
    st_atime: u64,
    st_mtime: u64,
    st_ctime: u64,
    // Field order, size, alignment exactly matches Linux
}

// ❌ Wrong: Define your own structures
#[repr(C)]
pub struct RuxStat {
    // ... Don't invent structures!
}
```

#### Filesystems
```rust
// ✅ Correct: Implement ext4 filesystem
// Reference Linux fs/ext4/ directory implementation

// ❌ Wrong: Invent new filesystem
// Don't create RuxFS or other "improved" filesystems
```

### Code Review Checklist

When reviewing code, must check:

1. [ ] Are system call numbers consistent with Linux?
2. [ ] Are data structure layouts consistent with Linux?
3. [ ] Does it follow POSIX standards?
4. [ ] Was Linux kernel source referenced?
5. [ ] Does it contain any "innovation"?

If code violating principles is found, it must be rejected and modification required.

## Development Recommendations
1. Determine module to modify (drivers/arch/mm, etc.)
2. Edit Rust code
3. Run `make build` to compile
4. Run `make test` to test
5. Run `make run` to verify

### Adding New Platform Support
1. Create `kernel/src/arch/<platform>/` directory
2. Implement boot.S, trap.rs, mm.rs, etc.
3. Add linker script
4. Configure Cargo target
5. Update documentation

### Adding New Drivers
1. Create subdirectory under `kernel/src/drivers/`
2. Implement driver trait/struct
3. Add configuration option in `Kernel.toml`
4. Register driver in initialization code
