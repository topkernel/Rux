缺陷分类学

全史内存破坏类缺陷逐条裁定:方法论、居留地统计、代表行、panic 面收编与负结果档案 —— 用数据回答"Rust 内核到底安不安全" · 正本:docs/architecture/safety-and-performance.md §2

§1方法论

  • 语料:main 可达的全部 3,358 个去重非合并提交主题(其中 2,702 个内核代码主题)+ 排查审计记录条目。
  • 筛选:以破坏/竞态/panic 词汇匹配出 169 个候选提交,逐条人工裁定,三轮清扫定稿(2026-11-03)。
  • 居留地判定:每个内存破坏行的修复 diff 逐块审读,确定缺陷驻留于显式 unsafe 块/架构汇编/unsafe 内部(UnsafeCell 分配器元数据、raw 指针协议)还是 safe 代码。
  • 口径纪律:仅遏制性提交不计为缺陷;revert-reland 对计一次;仪器误报不计入内核缺陷。

§2主统计

口径数量含义
内存破坏类缺陷(全史)33逐条带修复 commit 与复现/回归证据
—— 缺陷位于显式 unsafe 块/架构汇编/unsafe 内部23raw 指针协议、UnsafeCell 分配器元数据、trap 汇编

方法论自纠记录:初稿曾主张"safe 代码零缺陷"—— 全史扫描将其证伪(10 例 safe 所有权类),定稿改用居留地口径。结论由数据决定,不由叙事决定。

§3代表行

unsafe 类(3 例)

  • kthread pt_regs 零化:write_bytes 元素计数 168×168B,越界 28,224 字节覆盖相邻页(活 buffer-cache/inode 块被清零)(d047afad)。
  • x86 入口 EFLAGS.DF 脏标志:用户态置 DF 未清,rep movsb 反向拷贝(scribble 引擎根因)(e7070224)。
  • buddy split 终块未标已分配:同一内存块重复分发(FdTable 8KB Vec 破坏、fork 挂起)(016b3fa1;分配器内部 UnsafeCell 元数据)。

safe 类(3 例 —— 全部是类型系统今天的盲区)

  • vmscan 引用计数 ≤0 仍释放(zone 双重释放的使能者)(f4b67f66)→ 催化 checked Refcount newtype 提案(硬化缺口在册)。
  • GRQ 键控锁 swap 丢弃返回 guard:锁于语句末静默释放,全部临界区未互斥;13 次启动配对二分确认为根因;此后键控 guard 全部 #[must_use] —— 同型 API 缺陷现为编译警告(2b092c49/623c4736/75dbf637)。
  • PCACHE_SHARED 定为 bit 10:Sv39 中 bit 10 是 PPN[0],全部共享映射错位 4KiB 别名相邻帧(静默邻居页破坏);快照评审在任何启动之前捕获(6b49140b)。

评审捕获类(节选)

  • aarch64 boot.S DTB 指针寄存器占用(6e808eea);devfs Arc::as_ptr 无属主克隆("safe 存储 → unsafe 解引用"边界)(69f45692);io_uring SQE 索引未检裸读(5465735f);recvmsg 校验后重取用户 iovec(safe TOCTOU)(32fd359f)。

§4边界行(单列,不入 33 例)

  • mremap 原位扩展越合并邻居(56fc7e8b);R71 文件位置竞态(c17f6ec0);VMA 手术原子性(56b2baeb);ext4 陈旧 extent(2f9763fc);per-task program break(A/B 3/12 启动命中 → 0/12)(c127e4bc1/f6e3b8837)—— 语义级缺陷单独成档,避免与内存破坏类混淆。

§5panic 面:设计面而非潜伏面

内核的 panic 路径是设计出来的表面:每个已发现实例以回归测试消除,而非归档为 CVE 类。判据原则:响亮失败优于静默破坏 —— 边界检查把越界写拦截为 panic,而非让损坏继续传播。

  • 实证:pcp refill 竞态的越界存储命中边界检查,以显式 panic 终止("the len is 32 but the index is 32",165ee5fce)—— 竞态存在但破坏不可达。
  • 收编清单(节选):UTF-8 打印机族(非 UTF-8 comm 在 t=209s 击穿 panic 打印机,f0c57182/3ad32b9e)、负向查找缓存空解引用(ea26d923)、mmprof 槽命名空间(276c2e70)、dfx 开关表越界(363401cd)、memwatch PFN 界(cbd41b40)、R81 垃圾 pid(2c044bb5)、R73 栈走查界(9777f195)、taskdump(bf995f2a)、ext4 空索引根(b70a5deb)、aarch64 trap-report regs[31](363ac70b)、binder dead-proc expect→有界告警(619bf4b6)、定时器同 CPU IRQ 重入族(186a00b6)、Wave-1 十一项(83d0b691)、get_cwd UB + UTF-8 cmdline(830e3f8c)。

§6负结果档案(带收据)

  • 仪器同样被查出误诊:PTGUARD/FREEGUARD 为误诊(e61f7a3a);首版 PT_LEDGER 哈希设计产生假 DOUBLE-FREE 报告加真实帧泄漏(626658991200);2b092c49 的"潜伏 GRQ 竞态"理论错误。带收据的负结果保留在档案中 —— 判定纪律本身受审计。

§7结论:这些数字支持什么

  • 类别论证成立:表达式级缺陷类(0 例)与 safe 代码的结构性免疫一致;35 例中 23 例驻留于显式 audited unsafe —— 与"unsafe 面即 TCB"的分层模型自洽(0.27% = 1,022/375,622 行,审计记录页)。
  • 残余类明确:10 例 safe 类全部是所有权/引用计数/锁协议/栈深决策 —— 恰是模型检查与属性测试的靶(loom 锁协议、Kani INV-M 表、proptest 引用计数);硬化登记册将 checked Refcount、栈深分析列为闭合项。
  • 防线有效:6/33 在任何启动前被评审捕获;panic 面逐实例收编;仪器误判有档案。
  • 不含糊的表述:33 例/3,358 提交 ≈ 全史 1% 提交携带内存破坏缺陷,且全部带修复与回归证据 —— 这是"足够安全"的实证基线,而非断言。
