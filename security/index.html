§1核心命题

安全检查在编译期发生、从快路径消失 —— 快的设计与安全的设计是同一个设计。C 内核里安全与速度互换;Rux 把重要检查前移到类型系统与构建期,让快路径上不再有它们。§8 给出逐条"性能数字 ← 携带的安全性质"配对。

§3unsafe 表面与分层治理

  • 已枚举且带合同:unsafe 行占全内核 12.9%;Framework 层 1,340 个 unsafe token(逐块 // SAFETY: 注释覆盖 3,207/5,009 = 64%)。
  • service 层目标 100% forbid:47 个文件编译期 forbid(unsafe_code),另 56 个已无 unsafe;首个具名收缩目标 syscall/io.rs 69 个 token 已清零(typed entries + uaccess_safe 类型化 copy_in/copy_out)。
  • 分层模型(kernel-layers.md,最长前缀匹配,未匹配默认落最安全桶):Framework(arch/mm 原语/interrupt/virtio 核心/trace/perf)允许 unsafe;service 层 forbid;debug/ 诊断层单独统计;trace 模块整体禁 unsafe。
  • 胶囊边界:syscall 入口统一校验/翻译用户指针,内核其余部分不直接触用户内存。

§5运行时强化清单(已具备)

  • 用户/内核边界:SMAP(EFLAGS.AC 括号启用,D-18,~55 ns/括号,规避 TCG 下 STAC/CLAC #UD)、CR0.WP 自最早 boot、无恒等 MMIO 窗(D-17,uaccess 无恒等洞)、PF-NOCTX/SMAP-VIOL 信标全 suite 零。
  • 用户态:W^X(NX 映射、PT_GNU_STACK、READ_IMPLIES_EXEC)、seccomp(STRICT/FILTER + NO_NEW_PRIVS)、能力模型(41 个 CAP_* UAPI 编号)。
  • 内核栈护栏:栈 canary、深度探针(KSTACK-HW)、释放后 0xC3 涂绘环。
  • 延迟释放隔离:MmStruct/Task 进 16384 项定时环,1500 ms 排水,回收与使用期严格分离。
  • 失败纪律:Oops/panic 参考报告形状(CSR + 全 GPR + 32 帧回溯)、panic_on_oops sysctl、panic= 重启、pstore console。
  • 可观测的安全网:统一 tracepoint(51 事件/16 组)、census/heal 自愈、看门狗、kallsyms 符号化回溯。

§6panic 面是设计面,不是潜伏面

  • 每一处出现的 panic 都以回归测试消除(十余条收据在案):UTF-8 打印机族(非 UTF-8 comm 曾在 t=209s 击穿 panic 打印机)、负向查找缓存空解引用、mmprof 槽命名空间、debug 开关表、memwatch PFN 界、binder dead-proc expect→有界告警、timer 同 CPU IRQ 重入、ext4 空索引根、aarch64 regs[31]。
  • 原则:响而被捕获优于静默破坏 —— 边界检查把越界写拦成 panic,而不是让损坏继续走。
