安全总览

安全论证的枢纽页:核心命题、四个子页的地图与 headline 数字 —— 每个论断在子页内给出机制、数据与出处 · 活文档:docs/architecture/safety-and-performance.md(每轮合并持续收证)

§1核心命题

安全检查在编译期发生、从快路径消失 —— 快的设计与安全的设计是同一个设计。传统内核中安全与速度在快路径上互换;本内核将检查前移至类型系统与构建期,快路径不再支付该项成本。下方 §5 给出逐条"性能结果 ← 所携带安全性质"的配对实证。

§3复合论证:为什么这些数字构成"足够安全"

  1. 类别消除(编译期):统治 C 内核 CVE 史的表达式级缺陷(越界/迭代器失效/野指针运算/格式串)在 safe 代码中不可表达 —— 分类学的 0 例是该主张的实证面;unsafe 面收缩至 10.6% 且逐块审计。
  2. 残余类有专项应对:10 例 safe 类缺陷全部是所有权/引用计数/锁协议/栈深决策 —— 即模型检查与符号执行的靶:loom 交错枚举(启用头 90 秒捕获一例真实锁协议缺陷)、Kani 对全部输入证明不变量表、proptest 钉评分/编码/代数规则。
  3. 证明有效性有流程保证:镜像同步纪律使内核代码与被证副本的漂移直接 fail 构建 —— 证明不会随演化静默失效;CI 分层(per-push 轻量 + nightly 重型)保证装置实际运行。
  4. 缺陷面设计化:panic 路径逐实例收编(十余条回归测试收据);仪器误判与负结果带收据归档 —— 判定纪律自身受审计。
  5. 运行时防线 + 诚实缺口:SMAP/SUM/例外表/seccomp/能力/栈护栏具备且代价实测;缺口(KASLR、text W^X、栈保护等)逐项写明闭合形态而非回避。
