内存取证

泄漏、破坏、OOM 与用户态段错误的专用取证仪器 —— 每件仪器回答的问题、武装方式与判读方法 · 依据:kernel/src/dfx/、docs/guides/debugging.md

§1dfx=ledger:物理页总分类账

  • 回答的问题:"内存去哪了?" —— 全部受管页经单次描述符遍历、按优先序分类入桶(free_linked / free_orphan[≤LEAK] / reserved / page_tables[PT_LEDGER 精确位图] / anon / cow / mapped_file / lru_file / other_used),桶和回总到 zone 计数器,任何差额以显式 mismatch 行打印。
  • 判读:mismatch = 0 → 真空耗尽;mismatch > 0 → 记账漂移(泄漏或分类遗漏)。fake-OOM 家族(记账漂移伪装耗尽)与真空耗尽的判定依据即此。
  • 武装:dfx=ledger;OOM 时刻自动随取证块输出;UART 魔数 "LEDGER!" 触发。

§2dfx=mmforensics:页表与帧取证

  • 触发点:RAW-FREE watchpoint(Zone::free_pages)、活页表释放拒绝、PTLEDGER DOUBLE-FREE 拒绝、FUT-STALE-TREE 普查。
  • 输出:事件时刻的页描述符状态、PT 台账位、该帧的"化身历史"(取证环:PT_STAMP_RING —— 含盖章树的根、PT_FREE_RING、ZTRACE_ALLOC/ZTRACE_FREE、PTEI_RING 数据页安装)、per-CPU pageset 行,以及对内核反向映射缺失的补偿:有界扫描全部活任务的页表树,找出指向该 pfn 的链接。
  • 代价:fork/exit 热路径有计账开销 —— 仅排查期武装。

§3dfx=memwatch 与 allocwatch

  • memwatch:按尺寸类的 alloc/free 计数 + 大对象(2048<size≤4096)调用点直方图(前 4 个帧指针返回哈希);周期转储走 taskdump 原始 UART 路径 —— 泄漏定位首选。
  • allocwatch:跨 CPU 持锁者点名 —— 等待者不能自报(打印会分配,而它正卡在分配器内);scheduler_tick 跨 CPU 扫描全部戳记,报告持锁 >1 s 者及其任务状态。设计动机:分配器冻结家族的"镜像误报"判例(da27be84)—— 本仪器曾用于排除指控而非定罪,双向可用。

§4OOM 取证块

  • OOM 触发时的自动输出:SP-7 VscanCensus(逐页跳过原因)、直接回收门状态(持有者 pid + RECLAIM_GATE_EXIT_RELEASES 计数)、ledger 桶和、oom_control 细节(chosen/chosen_points/totalpages)。
  • 判读路径:先 ledger mismatch → 若为记账漂移,PT_LEDGER 位图与 anon/cow 桶定位漂移源;若真耗尽,VscanCensus 的 rc2/rc3/rc4 行定位回收失效分支。

§5用户态段错误取证:USEGV 家族

  • USEGV-L:用户态 SIGSEGV 的结构化行(pid/rip/cr2)—— 内核侧无 panic 时用户态崩溃的第一读取点。
  • USEGV-FOR:cr2 落点归因 —— 例:"cr2 INSIDE BINDER BUFFER of proc … — stale daemon mapping dropped at fork (DONTFORK)":cr2 位于某进程 binder 缓冲区内 + fork 时陈旧守护映射被丢弃的注记,直接点名缺陷族。
  • shmat1 类测试自身缺陷的定责即依赖该行(宿主基线交叉表 + cr2 落点)。

§6scribble 家族:控制字涂写猎捕

  • 对 thread.{fs_base,gs_base,sp,callee.ret_addr} 与停放的 pt_regs 控制字建立影子 canary;静息点与 tick 双验证 —— 野写命中即报。
  • scribblepark / scribblepid1 / scribblesweep:命中即停靠,配 GDB watchpoint 反向定位写入者(pty 深嵌套栈溢出事故即由此定位:memcpy at sp 低于栈底)。

§7挂起与软死锁检测

  • hung_task(khungtaskd):TASK_UNINTERRUPTIBLE 且上下文切换计数不变的任务;HUNG_TASK_TIMEOUT_SECS = 120,检查间隔 = 超时/2。
  • softlockup:per-CPU 时间戳于 scheduler_tick 更新,阈值 10 s。
  • sysrq(/proc/sysrq-trigger):已实现 c(故意 panic)/d(持锁展示)/i(kill-all 除 init)/t(taskdump)/s(sync);未实现项打印显式提示(SAK/RT-nice 等)。

§8离线镜像取证(不启动)

debugfs -R "cat /var/log/kmsg" <拷贝盘.img>   # 崩溃后抽内核日志
e2fsck -f <拷贝盘.img>                          # 镜像完整性
  • 持久日志开启后 panic 日志幸存于 /var/log/kmsg(kernel/src/main.rs 单行开关);崩溃现场无活机时此为唯一日志源。
  • 拷盘用 reflink(宿主 cp --reflink)避免改写原盘;所有启动一律 -snapshot + file.locking=off。

§9判读速查

症状仪器路径
怀疑泄漏dfx=memwatch 按调用点记账 → 分配器卡死者用 allocwatch 点名 → ledger 确认总量
OOM 报告可信吗ledger mismatch 判真耗尽/记账漂移 → VscanCensus 定回收失效分支
双重分配/帧破坏dfx=mmforensics:PT 台账 + 戳环给帧化身史 + 全任务反向扫描找持有者
野写scribble canary 命中停靠 → GDB watchpoint 定写入者
用户态崩溃USEGV-L 行定 pid/rip/cr2 → USEGV-FOR 归因 cr2 落点
堆破坏(brk 类)TRIMQ 类隔离区仪器在专用狩猎线(lane 分支);主线用 mmforensics + scribble 组合
崩溃后无活机debugfs 离线抽 /var/log/kmsg → e2fsck -f 验镜像
