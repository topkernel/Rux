panic 与符号化

内核 panic 报告结构、kallsyms 编译期符号表、oops 形态与行原子转储 —— 从一段串口输出到源码行号的完整流程 · 依据:kernel/src/dfx/(backtrace/oops/ksyms)、arch/*/trap.rs、design-divergences.md(D-3)

§1panic 报告结构

panic 处理器绕过日志级别直写 UART,随后 wfi 停机。一份完整报告包含:

  1. PANIC 消息 + file:line(panic! 的参数与源位置);
  2. CSR 四件套(riscv64):sstatus / scause / stval / sepc;x86_64 对应 cr2/rip/rsp/错误码;
  3. 全部 31 个通用寄存器(riscv64)—— 在任意栈展开前由内联汇编保存;
  4. 调用栈回溯:沿帧指针链(s0/fp;riscv64 / rbp;x86_64)最多 32 帧 Call trace:。
字段读法
scause位 63 置位 = 中断;异常码:0 非对齐取指、2 非法指令、8 U 态 ecall、12 取指缺页、13 读缺页、15 写/AMO 缺页;中断码:5 时钟、9 外部
sepc引发陷入的指令地址
stval缺页时 = 出错虚拟地址;非法指令时 = 指令位
Call trace首地址为 panic 函数的返回地址(ra),其后逐层为调用者返回地址

§2编译期符号表(D-3)

  • 构建:构建期对链接 ELF 执行 nm + addr2line -C(demangle),压缩为 NUL 分隔名称 blob + (offset, address, size, type) 索引,入 .rodata;仅文本符号,两遍构建。
  • 规模:~22.6k 符号,2.4MB 名 + 0.7MB 索引;镜像 +3.1MB(riscv64 曾因此同步移动 boot 窗/堆基/RAM 预留 14→18MB;x86_64 映射自运行时 __kernel_end 派生,无需移动)。
  • 启动开销:零 —— 数据在镜像内,无运行期扫描。
  • 消费方:/proc/kallsyms(标准 addr type name 行,22,636 行,覆盖至 _etext)、Oops/回溯的原生符号化(%ps 形态 name+0xoff/0xsize,非文本符号以 ? 标注)、回溯器。
  • 守卫:scripts/test/kallsyms-smoke.sh 钉住符号覆盖;交叉构建按 target-triple 忽略陈旧表。

§3oops 形态

  • 内核态缺页的处理序:例外表 → fixup(rip = fixup 地址)→ KernelPanic;oops 打印带重入闩(防野帧指针引发递归转储)。
  • USEGV 家族(x86_64):用户态段错误结构化行 —— 详见内存取证 §5;PF-NOCTX 信标在 oops 机制污染上下文前点名裸用户指针解引用(SMAP 语境)。
  • %ps 符号化:回溯行内直接给出 symbol+0xoff/0xsize,无需离线 addr2line 即可初判;精确行号仍走 addr2line。

§4行原子转储(printk 发送纪律)

  • 逐 CPU 暂存批量 TX,持 printk 发送锁有界获取(Full 50 ms / Brief 100 µs)—— 实测:多任务并发转储下的破损任务行 1.7% → 0(1506/1506 行完形)。
  • 动机:并发转储交错曾使取证行彼此截断 —— 一段不可信的现场等于没有现场。

§5REMOTE-BT:跨 CPU 栈捕获

  • dfx-lock-owner feature 下,看门狗/取证路径可经 IRQ_WORK IPI 请求远端 CPU 的栈快照 —— 持锁者自身 IF=0 时其 tick 已死,只能由其他 CPU 观察。
  • 配合 allocwatch 的跨 CPU 持锁者点名构成完整的"谁持有"取证对。

§6符号化工作流

# 1. 逐地址符号化(跨架构选对应工具链)
riscv64-linux-gnu-addr2line -e <kernel.elf> -f -C <addr> [addr2 addr3 ...]
x86_64-linux-gnu-addr2line -e <bzImage 对应 vmlinux> -f -C <addr>
# 2. 一次喂入整条 Call trace 的全部地址
# 3. 交叉核对:/proc/kallsyms 的符号边界(若 guest 仍活着)
  • bzImage 的符号化:构建时保留未剥离 ELF(kbuild 产物),addr2line -e 指向它;运行时 /proc/kallsyms 地址与 ELF 符号表一致(链接地址即运行地址)。
  • release 构建的符号表默认为 371 字节 stub(kallsyms_generated.rs)—— 需要符号化的诊断构建以 feature 重开;两条镜像尺寸口径(12.2MB vs 16.0MB)差异即此。

§7从串口到根因的完整链路

  1. 捕获:串口落盘(-serial file:)或 hunt-wedge 自动抓取;
  2. 定类:scause/cr2 判异常类;panic 消息 + file:line 初判;
  3. 定位:Call trace 全地址一次性 addr2line → 定位函数与行;
  4. 取景:需要更多现场 → dfx=mmforensics / dfx=watchdog / REMOTE-BT 重跑;
  5. 定罪:确定性复现(THREAD=single)+ 多启动取交集。
