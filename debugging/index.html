调试

日志 · panic 取证 · trace 体系 · debug 开关 · 死锁检测 · 性能调试 · 内存取证 · GDB —— 汇总仓库 docs/guides/debugging.md 与 kernel/src/debug/、kernel/src/trace/ 的全部可用手段

§1内核日志

  • 串口是首要日志(console=ttyS0):启动期全部打印到 UART;调度器就绪后默认级别降为 emerg(只留紧急),用户态 dmesg -n 7 重新打开全量控制台输出。
  • 日志级别 0–7与参考内核一致(emerg…debug);宏:pr_emerg! / pr_err! / pr_warn! / pr_info! / pr_debug!(println! 是 pr_info! 的别名)。
  • kmsg 环形缓冲 1 MB:所有消息进环,读取途径 /proc/kmsg、syslog(2)(action 2/3)、dmesg。
  • 持久日志(默认关):开启后 panic 日志跨重启幸存于 /var/log/kmsg(kernel/src/main.rs 中去掉一行注释即开);崩溃后可用 debugfs 离线抽取(见 §7)。

§2panic 取证

panic 处理器绕过日志级别直写 UART,然后 wfi 停机。一份完整报告包含:

  • PANIC 消息 + file:line(panic! 的参数与源位置)
  • CSR 四件套:sstatus / scause / stval / sepc
  • 全部 31 个通用寄存器(在任意栈展开前由内联汇编保存)
  • 调用栈回溯:沿帧指针链(s0/fp)最多 32 帧 Call trace:

怎么读

字段读法
scause位 63 置位 = 中断;异常码:0 非对齐取指、2 非法指令、8 U 态 ecall、12 取指缺页、13 读缺页、15 写/AMO 缺页;中断码:5 时钟、9 外部
sepc引发陷入的指令地址
stval缺页时 = 出错虚拟地址;非法指令时 = 指令位
Call trace第一个地址是 panic 函数的返回地址(ra),其后逐层是调用者的返回地址

符号化

riscv64-linux-gnu-addr2line -e <kernel.elf> -f -C <addr>   # 逐地址
# x86_64 用 x86_64-linux-gnu-addr2line;trace 里的多地址可一条命令全喂进去

编译期符号表(D-3)同时提供 /proc/kallsyms(22.6k 符号)与 Oops/回溯的原生符号化;kallsyms-smoke.sh 钉住符号覆盖。

§3trace 体系(统一 tracepoint + tracefs)

新观测一律走这里(观测性政策,2026-11-02)。单声明表(D-15)一行定义一个事件的全部面貌:组/名/id/逐字 print fmt/字段表/typed 记录函数/渲染器。当前 61 事件 / 20 组:sched(9)、ext4(7)、lock(6)、rux(5)、net(5)、binder(5)、kmem(4)、tcp(3)、raw_syscalls / jbd2 / irq / exceptions / block(各 2)、vmscan / timer / sock / signal / printk / oom(各 1)。

文件树(/sys/kernel/tracing,对齐参考实现)

mount -t tracefs none /sys/kernel/tracing
cd /sys/kernel/tracing
ls
# tracing_on  trace  trace_pipe  available_events  available_tracers
# current_tracer  set_event  buffer_size_kb  snapshot  options/  events/…
ls events/sched/                       # 每组一个目录
cat events/sched/sched_wakeup/format   # 字段表 + print fmt(逐字节对齐参考实现)

典型用法

echo 1 > tracing_on                                  # 总开关(两级门控的第二级)
echo 1 > events/sched/sched_wakeup/enable            # 单事件
echo 'sched:* kmem:*' > set_event                     # 按组批量;支持通配与否定(!event)
cat trace                                            # 读缓冲(读后不清空;写 1 到 trace 清空)
cat trace_pipe                                       # 消费式读取,无表头
echo 1 > buffer_size_kb                              # 每 CPU 环大小(KiB)
echo 1 > snapshot                                    # 把当前环存档到 snapshot,事后 cat snapshot

成本:未武装站点编译为一个 load+test+branch(release 反汇编逐点验证);启用后 +13–19 ns/记录,镜像价 +0.18%。事件禁用时调用点只付参数求值。

§4debug= 运行时开关(遗留诊断面,冻结)

启动参数 debug=开关1,开关2(逗号分隔)。权威表 = kernel/src/debug/switches.rs 的 debug_switch_table!(67 项,冻结不再增长——新观测请走 §3 tracepoint);sysrq/debugfs 在 /sys/kernel/debug/debug/ 镜像同一张表。常用项:

开关用途
watchdog自旋锁死锁告警后自动打印全任务快照(经 SBI 直写,不依赖 printk)
taskdump按需任务快照钩子
memwatch按调用点的堆/页记账(查泄漏)
mmforensicsmm 取证环:PTE 安装台账、双重拆卸检测、页表戳环(fork/exit 热路径有代价,仅排查用)
scribble / scribblepark任务控制字逐字节涂写猎捕;命中即停靠,配 gdb watchpoint
schedtrace / steptrace / writetrace / syscalltrace调度步进 / 指令步进 / 写路径 / 系统调用摘要的逐事件跟踪
sysforensic / sysring逐系统调用取证(SYSCALL_RING 双录、失败环、comm 扫描钩子)——生产必须关(未门控时 p1_null 每调用多付 12 次原子)
sysefault点名每个返回 -EFAULT 的系统调用(限速)
ohhuntOH 图形排查探针(drm ioctl/mmap/prime-import 跟踪)
wwcensus唤醒-等待普查心跳(性能门 census 启动)
trimq=1brk 收缩隔离区:TRIMQ-HIT/PRESENT/FRAME 三段取证(谁、何时、收缩时页面是否活、帧内容今昔对比)
dlsleep / dlspinlockdep-lite 的睡眠/自旋锁观测开关(P1 起)

编译期 feature(Cargo.toml)

cargo build --target riscv64gc-unknown-none-elf --features riscv64,debug-lock-owner
# debug-lock-owner:每次加/解锁一次原子存储;死锁告警带 holder=<cpu>

§5死锁与挂起检测

三道既有防线

防线机制覆盖面
编译期栅栏类型化锁键(D-11):嵌套对在 lock-ordering.md 里具名后可上键,反向嵌套不再编译已迁移的具名对(GRQ/桶、等待槽/桶)
自旋看门狗RawSpinlock::DEADLOCK_WARN_ITERS:自旋 ~1 亿次打印告警;debug=watchdog 时自动全任务快照在活 CPU 上真的长时间自旋的死锁
SPIN 模型kernel/verify/spin/lock_ordering.pml(make spin):对已文档化路径做无死锁证明被建模的抽象路径,模型检查期

lockdep-lite(设计已采纳,P0 已落地)

补上未覆盖类:未具名锁对 + 未建模路径上的违规获取顺序。不复制参考实现的形态,用 Rust 原生机制:静态锁类站点声明 + 运行期把每次持锁嵌套记为图边、新边即时查环,在死锁发生前带两类锁名与获取点 splat。P0(静态顺序注册表 + 启动期校验)已在主线;P1/P2(运行期记录)在实现线。debug=dlsleep,dlspin 是它的观测开关。

hunt-wedge:自动捕获

./test/hunt-wedge.sh [rounds]   # 默认 6 轮;捕获即停。退出码 0=抓到, 2=未复现

自动构建带 debug-lock-owner 的内核,循环注入 smoke + nettest + pipe-bomb 负载,盯两类挂起(A 类:锁死锁告警;B 类:管道 >30 s 无输出)。命中即经 QEMU monitor 抓每 CPU 寄存器/栈/反汇编到 /tmp/rux-hunt/,并保留当轮 kernel.elf 供 addr2line。分析三步:从 hunt.log 分类挂起类型 → addr2line -e /tmp/rux-hunt/kernel.elf -f -C 符号化 hunt.dump 的 pc=/ra= → 扫栈字里的内核 ra 值还原调用链。

§7内存与文件系统取证

  • memwatch(debug=):按调用点的堆/页记账,泄漏定位首选。
  • allocwatch:跨 CPU 持锁者命名 —— 等待者不能自报(打印会分配,而它正卡在分配器里),由观察者点名。
  • mmforensics(debug=):PTE 安装台账、双重拆卸检测、页表戳环。
  • TRIMQ(boot 参数 trimq=1):brk 收缩隔离区,TRIMQ-HIT(谁/何时/age)+ TRIMQ-PRESENT(收缩时页面是否活)+ TRIMQ-FRAME(帧内容今昔)三段取证;GNOME 堆破坏排查的主仪器。
  • ledger:OOM 时刻物理账核对(zone 余量/匿名/文件 LRU/脏页,判定是真空耗尽还是记账漂移)。
  • USEGV-FOR:用户态缺页取证行(cr2 落点、vma 命中与否),shmat1 之类测试缺陷就是靠它定责的。
  • 离线镜像取证(不启动):debugfs -R "cat /var/log/kmsg" 拷贝盘.img;镜像完整性 e2fsck -f。
  • scribble(debug=):任务控制字涂写猎捕,命中停靠配 gdb watchpoint。

§8GDB 与 QEMU 级调试

  • GDB:make debug(先 make build;连 QEMU 的 gdbstub,断点/单步/查内存)。
  • 确定性复现:THREAD=single make run(单线程 TCG);或 ACCEL=tcg 关 KVM。
  • QEMU monitor:经 unix socket 挂接(oh-boot.sh 的形态),screendump 抓屏、寄存器/内存转储(hunt-wedge 自动用)。
  • 串口落盘:-serial file:xxx.log,长浸泡后离线 grep。

§9场景速查

症状路线
内核挂起无输出换 THREAD=single 复现 → debug=watchdog 看死锁告警 → ./test/hunt-wedge.sh 自动捕获 → addr2line 符号化
内核缺页/非法指令读 panic 块(§2):scause 定类、stval 定址 → addr2line Call trace → 需要更多现场加 mmforensics
用户态程序崩溃grep 串口的 USEGV-FOR 行(cr2/vma);内核侧无 panic 即优先疑用户态
文件系统问题先看 fsw 计数器有无新同步写类 → 拷盘 debugfs 离线抽日志 → e2fsck -f 验完整性
怀疑泄漏debug=memwatch 按调用点记账;分配器卡死者用 allocwatch 点名
堆破坏(trim 类)trimq=1 隔离区抓首触;TRIMQ-FRAME 看帧内容今昔
锁竞争/顺序trace lock:* 事件看延迟;debug=dlsleep,dlspin(lockdep-lite);命名对上键(D-11)让反向不再编译
