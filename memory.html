内存管理

概述

Rux 内核的内存管理子系统完全对齐 Linux RISC-V 的实现方式，包括：

  • Linux 风格的 Memblock 早期内存管理器
  • 从设备树动态发现内存区域
  • 混合页表分配策略（静态 + 动态）
  • Frame Allocator 物理页帧分配
  • 用户进程地址空间管理

地址空间布局

Sv39 分页模式

Rux 使用 RISC-V Sv39 三级页表，与 Linux 完全一致：

区域 起始地址 结束地址 大小 描述
用户空间 0x00000000_00000000 0x0000007f_ffffffff 256 GiB 用户代码、数据、堆、栈
内核空间 0xffffffc0_00000000 0xffffffc0_ffffffff 4 GiB 内核映射（暂未使用）
物理恒等映射 0x80000000 动态 可变 物理内存恒等映射

关键常量

// Sv39 页表参数
pub const VA_BITS: u64 = 39;
pub const PAGE_SIZE: u64 = 4096;
pub const PTRS_PER_PTE: u64 = 512;

// 页表层级偏移
pub const PGDIR_SHIFT: u64 = 30;  // PGD 映射 1GB
pub const PMD_SHIFT: u64 = 21;    // PMD 映射 2MB
pub const PAGE_SHIFT: u64 = 12;   // Page 映射 4KB

// 地址空间划分
pub const TASK_SIZE: usize = PGDIR_SIZE * PTRS_PER_PGD / 2;  // 256 GiB

Memblock - 早期内存管理器

概述

Memblock 是 Linux 风格的早期内存管理器，用于在 Buddy Allocator 初始化之前管理内存。它替代了之前的硬编码内存区域计算方式。

核心数据结构

/// 内存区域标志
pub struct MemBlockFlags: u32 {
    const NONE = 0;
    const HOTPLUG = 1 << 0;    // 支持热插拔
    const NOMAP = 1 << 1;      // 不创建映射
    const MIRROR = 1 << 2;     // 镜像内存
}

/// 内存区域描述符
pub struct MemBlockRegion {
    pub base: usize,           // 物理起始地址
    pub size: usize,           // 区域大小（字节）
    pub flags: MemBlockFlags,  // 区域标志
    pub nid: u32,              // NUMA 节点 ID
}

/// Memblock 管理器
pub struct MemBlock {
    memory: MemBlockType,      // 可用内存区域（来自设备树）
    reserved: MemBlockType,    // 保留区域（内核、堆等）
    initialized: AtomicBool,
    bottom: usize,             // 可用内存底部
    top: usize,                // 可用内存顶部
}

API 接口

函数 描述
memblock_init() 初始化 memblock
memblock_add(base, size) 添加内存区域（来自设备树）
memblock_reserve(base, size) 保留内存区域
memblock_remove(base, size) 移除内存区域
memblock_get_available_region() 获取第一个可用区域
memblock_total_memory() 获取总内存大小
memblock_available_memory() 获取可用内存大小

初始化流程

// 1. 初始化 memblock
mm::memblock_init();

// 2. 从设备树解析内存区域
let memory_regions = unsafe { cmdline::parse_memory_regions(dtb_ptr) };
for region in &memory_regions {
    mm::memblock_add(region.base, region.size).ok();
}

// 3. 保留已使用的区域
mm::memblock_reserve(0x80000000, 0xA00000).ok();       // OpenSBI + kernel
mm::memblock_reserve(heap_start, heap_size).ok();       // Heap
mm::memblock_reserve(slab_start, slab_size).ok();       // Slab
mm::memblock_reserve(0x84000000, 0x4000000).ok();       // User phys alloc

// 4. 从 memblock 获取 frame allocator 起始位置
let frame_alloc_start = mm::memblock_get_available_region()
    .map(|r| r.base)
    .unwrap_or(0x88000000);

页表管理

混合分配策略

Rux 使用混合策略进行页表分配：

  1. 早期启动（静态）：预分配的 `.pagetables` 段
  2. Frame Allocator 就绪后（动态）：从 Frame Allocator 动态分配
const MAX_KERNEL_PAGE_TABLES: usize = 256;

#[link_section = ".pagetables"]
static mut KERNEL_PAGE_TABLES: [PageTable; MAX_KERNEL_PAGE_TABLES] = [...];

static FRAME_ALLOCATOR_READY: AtomicBool = AtomicBool::new(false);

unsafe fn alloc_page_table() -> Option<&'static mut PageTable> {
    if is_frame_allocator_ready() {
        // 动态分配
        let frame = alloc_kernel_page()?;
        let phys_addr = frame.start_address().as_usize() as u64;
        core::ptr::write_bytes(phys_addr as *mut u8, 0, PAGE_SIZE as usize);
        Some(&mut *(phys_addr as *mut PageTable))
    } else {
        // 静态分配（早期启动）
        let idx = KERNEL_PT_NEXT.fetch_add(1, Ordering::AcqRel);
        Some(&mut KERNEL_PAGE_TABLES[idx])
    }
}

页表释放

进程退出时，其页表会被自动释放：

// MmStruct 的 Drop 实现
impl Drop for MmStruct {
    fn drop(&mut self) {
        if self.space_type == PageTableType::User {
            unsafe {
                crate::arch::mm::free_user_page_tables(self.pgd);
            }
        }
    }
}

Frame Allocator

概述

Frame Allocator 负责物理页帧的分配和释放。它从 memblock 获取的可用内存区域开始分配。

初始化

// 从 memblock 动态获取起始位置
let frame_alloc_start = mm::memblock_get_available_region()
    .map(|r| r.base)
    .unwrap_or(0x88000000);

let frame_alloc_start_pfn = frame_alloc_start / mm::PAGE_SIZE;
mm::page::init_frame_allocator(frame_alloc_start_pfn);

// 通知页表分配器可以开始动态分配
arch::mm::frame_allocator_ready();
