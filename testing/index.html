§3测试形态总览

  • 内核内套件(make test):73 个测试文件、八大门类(memory / process / fs / ipc / signal / network / driver / syscall);断言全部在 QEMU guest 内运行(内核 crate 无法承载宿主侧 #[cfg(test)])。CI 冒烟门(smoke.yml)每次 push 跑 riscv64 腿。
  • 集成舰队:多腿无人值守 + 探针矩阵(integration-test-report.md);GUI 有 23 项像素/串口检查门(test/ubuntu-gui/verify.py),两次独立启动逐像素一致性判定。
  • 形式验证:1104 proptest 每次 push 绑定跑;Kani(157 harness)/ SPIN / Miri nightly(详见安全栏目)。
  • 仓库测试总量 4,200+ 用例(套件 + 探针 + 基准 + 验证)。

§4方法与裁决纪律

  • 每个数字带 rig:架构、加速器、内核 profile、宿主负载纪律 —— 没有 rig 的数字不算结果。
  • 报告追加式:新一轮追加小节或刷新常设表并注明日期,不静默改写历史。
  • 抖动隔离:全量扫描新失败一律隔离复跑 2 次再定性为回归(已知抖动例:accept02、getrusage04、kill02、genfmod、rename/statfs 族)。
  • NOT-OURS 台账:同一 musl 版 LTP 二进制跑在宿主 Linux 内核上,判定一致的失败记为测试/环境问题而非内核缺口。
  • 仪器误诊也归档:PTGUARD/FREEGUARD 误判(mapcount=−1 是哨兵)、首版 PT_LEDGER 假双自由 —— 带收据的阴性结果留在记录里。
