CI 流水线(make ci)

一键完整回归:构建 → 套件 → 镜像 → 启动回归 + 基准 → LTP 全量 → 压力循环 —— 无人值守,无需 LLM · 实现 userspace/ci/(2026-11-10)
定位:任何人(或任何定时器)在仓库根目录运行 make ci,即可得到一轮完整测试;每日压力流水线(daily-stress.sh)以同一套阶段循环驱动。全部产物落 run/ci-*.log 与 userspace/ci/<日期>/;任一阶段检出 KERNPANIC 即写 ALERT 并停机 —— 这是唯一需要人工介入的条件。

§1六个阶段

#阶段内容状态
1内核构建PLATFORM=x86_64 make build,产物 bzImage已接
2套件编译fio / rt-tests / futex-selftests / fsfuzz 静态构建(x86_64 musl)已接
3guest 镜像从资产库播种(缺则回退仓库原生 target 生成;镜像不可下载,只从常备镜像库 reflink 播种)已接
4aUbuntu 启动回归脚本化串口靴 420 s(KVM q35 4G/4CPU,-snapshot);login / gnome-shell / Ubuntu 标记判定通过,KERNPANIC 检出即 UBUNTU-REGRESS已接
4bOH 启动回归双盘靴(system + userdata)600 s(KVM q35 2G/2CPU);"insert SA:" 插入数 ≥20 判活,KERNPANIC 检出即 OH-REGRESS已接
4clmbench / Geekbench资产自动获取已接(lmbench 源码下载编译、Geekbench 6 tarball,入库后存在即跳过);注入跑分与 CSV 解析接入 rig 中PENDING-RIG
5LTP 全量扫描1,869 项全量,setsid 脱离启动,完成后结果落行(log run/ci-ltp.log)已接
6压力 32 类循环3 槽 QEMU 循环(fio / futex / rt-tests / fsfuzz 类,finite pass 或每日循环直到 stop);裁决追加 rounds.log已接

§2每日循环(daily-stress.sh)

按同一阶段序循环驱动:bootreg → bench → LTP → 压力循环(直到 daily-stress.sh stop);每阶段日志落 userspace/ci/<日期>/。fio/cyclictest 的性能行随轮解析。启动:bash userspace/ci/daily-stress.sh start,查状态:status,停止:stop。

§3资产库纪律

  • 位置:默认 ~/rux-assets(git 之外;RUX_ASSETS 可覆盖),分 images / src / bin / logs 四区。
  • 只读优先:脚本只读;仅当资产缺失时才播种/更新 —— 存在即跳过,新鲜度以存在性为准。
  • 镜像不可下载:从常备镜像库(/home/william/rux-images)reflink 播种;无种子且生成失败时明确报 ASSET-MISSING,不静默跳过。
  • 源码按需取:lmbench 从 upstream 下载编译、Geekbench 6 tarball 展开入库,产物只构建一次。

§4用法

make ci                            # 一轮完整流水线(构建→套件→镜像→启动回归→LTP→压力 finite pass)
bash userspace/ci/daily-stress.sh start   # 每日循环模式
bash userspace/ci/daily-stress.sh status  # 各阶段状态
bash userspace/ci/stress-fleet.sh log 20  # 压力循环尾部日志
