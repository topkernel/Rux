fio 3.36

存储 I/O 性能对照(同机同镜像同二进制):吞吐与延迟,无数据引擎行即不可用 · 测试平台与方法

§1数据(同机同镜像同二进制对照)

两侧使用同一 ext4 镜像、同一静态 fio 3.36 二进制、同一作业文件,Rux(main release)与 Linux(同镜像 guest 内核 7.0.0-38)于同一测试平台(q35/KVM/-cpu host/SMP8/8G,virtio-blk;交替启动测试 3 轮取中位数)执行;direct=1 绕过页缓存。每行取最新实测值;同一测量窗口内内核对内核比值随宿主负载窗口两侧同浮动(±10% 级),比值只在同一测量窗口内有意义。无数字的引擎行即当前不可用。

§2优化方法

差距归因用两侧同机对账(两内核在同一镜像/负载下,用共享 tracefs 事件时间线 + 相位周期括号 + 双方 perf 把每 op 成本逐段对账:系统调用入口/块解析/提交+kick/设备/完成中断/唤醒/返回),再按 Linux 的实现形态逐项改造:直读路径按物理连续段批量提交;MSI-X + 完成处理内联硬中断向量;同步等待先有界轮询后睡眠(完成对象是纯内核值,深度 1 时整套睡眠机械比设备往返还贵——Linux 同取舍,仅 opt-in);未写盘区成批转换+邻接合并(每写跨度一次树编辑);每 inode 脏块笔记 → O(dirty) fsync 扫描(tagged page tree 类比)+ inode 表块搭同一刷写窗口;缓冲写用户页直拷入页缓存帧(copy_page_from_iter 形状);目录读取增量填充;路径/描述符成本(close 条件引用获取=fget_rcu 形状、readahead 状态内嵌 File);地址空间回收释放空页表。每项改造同机同镜像同二进制 A/B;负结果留档(MSI 目标重定向在本 QEMU/KVM+irqfd 下为死胡同)。方法与逐项证据见 docs/test/perf-campaign-2026-11-17.md。

§3测试平台与方法

  • 对照组:Rux(main release)vs Linux(同镜像 guest 内核 7.0.0-38),同一 QEMU q35 + KVM(-cpu host SMP8/8G),同一 ext4 镜像(reflink 拷贝,snapshot 启动),同一静态二进制(源码 tar 包入 git,userspace/fio/build-x86.sh 构建);交替启动测试 3 轮取中位数。
  • 协议:每侧一次启动顺序执行全部作业(qsrun cmds 协议);fio terse 单行输出进串口采集,含 bw/IOPS/延迟字段。
  • 口径:direct=1 行为真实设备路径;缓冲写行为页缓存吸收口径(两侧同);比值只在其会话内有意义。
