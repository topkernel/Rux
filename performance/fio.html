fio 3.36

存储 I/O 性能对照(同机同镜像同二进制):吞吐与延迟,无数据引擎行即不可用 · 机位与方法

§1数据(同机同镜像同二进制对照)

两侧使用同一 ext4 镜像、同一静态 fio 3.36 二进制、同一作业文件,分别在 Rux(main debug)与 Linux(宿主 7.0.0 内核)于同一 guest 机位(q35/KVM/-cpu host/smp2/2G,virtio-blk)执行;direct=1 绕过页缓存。每行取最新实测值;无数字的引擎行即当前不可用。

libaio(io_setup/io_submit)—有—

无数据行:libaio 为 UAPI 未实现(io_setup ENOSYS);io_uring 的 enter 契约触发用户态崩溃(环形语义未完成)。posixaio 引擎可运行,其吞吐读数并入扩展作业队列。作业尺寸上限(48M)由镜像剩余空间约束,两侧同约束。

§2机位与方法

  • 对照对:Rux(main debug)vs Linux 宿主内核 7.0.0,同一 QEMU q35 + KVM(-cpu host smp2/2G),同一 ext4 镜像(reflink 拷贝,snapshot=on 启动),同一静态二进制(源码 tar 包入 git,userspace/fio/build-x86.sh 构建)。
  • 协议:每侧一次启动顺序执行全部作业(qsrun cmds 协议);fio terse 单行输出进串口采集,含 bw/IOPS/延迟字段。
  • 口径:direct=1 行为真实设备路径;缓冲写行为页缓存吸收口径(两侧同);比值只在其会话内有意义。

§3扩展

# 追加作业:userspace/ci/classes/ 下新增 .cmds(行格式:<预算秒> fio --name=... --filename=/test/qa/...)
# 双侧对照:run/bench-pair.sh(Rux 臂 + Linux 臂,同镜像同 cmds)
延迟百分位(dump JSON)受 qsrun 尾部截断限制,terse 单行为现行采集口径;逐作业延迟分级采集在补测队列。
