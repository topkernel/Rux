§1结论:与 Linux 相比领先多少、落后多少

本页所有与 Linux 的对照均为同机同加速:同一宿主(9950X)、同一 QEMU q35 + KVM(-accel kvm -cpu host)、同一镜像形状、同一静态基准二进制。不含任何裸机对照。

📏lmbench 同机对照:14 项中 9 项领先、5 项落后

领先:缺页延迟 2.26–2.45×、lat_mmap 4.2×、管道 3.56×、上下文切换 3.39×、lat_unix 3.14×、lat_sem 2.62×、bw_pipe 2.68×、bw_unix 1.88×、lat_syscall read 1.02×。

落后(Rux/Linux):open 1.82×、stat 1.32×、null 1.17×、fork 1.11×、write 1.10×。

领先最高 4.2× · 落后最大 1.82× · 数据见 §2

🏁Geekbench 5:多核总分领先 4.3%、单核总分领先 5.1%

多核总分 7332 vs 7027(+4.3%):21 项负载 8 领先 / 5 持平 / 8 落后。单核总分 quiet 最佳 2274 vs 2165(+5.1%):13 领先 / 3 持平 / 5 落后。

逐项数据见 §3 · 机位注明:Linux 侧为宿主 4-CPU 钉核(taskset,拓扑对齐)
差距结构:领先面覆盖调度/唤醒(上下文切换、管道)、缺页/映射(七轮 campaign 把缺页从落后最大项做成领先 2.26–2.45×)与 IPC 带宽;落后面收窄到系统调用入口与路径解析(open 1.82×、stat 1.32×)、fork(1.11×)—— write 距持平仅 6 ns,read 已反超。数据来自 perf-gap-hunt 七轮 campaign(每行同窗交错 A/B,med-of-3+3)。

§4方法与 rig

  • 同机同加速:两侧同一宿主、同一 QEMU q35 + KVM(-accel kvm -cpu host)、同一 Ubuntu rootfs 形状、同一静态基准二进制;每启动一个用例(串口与长基准并发打印,单用例单次启动是唯一干净采集),runner 为 PID 1,35 秒 in-guest 预算(特殊用例单独注明)。
  • 类内可比铁律:debug 与 release-strong 不可跨类比(strong 在下限类指标低 10–30×);TCG 与 KVM 不可跨类比。
  • 锚溯源:锚只读 Rux 自身中位 —— Linux 列永远不进 Rux 门锚(leg 32 曾发现四格误抄自 Linux 列,已纠错并留档)。

§5合并门性能维度(三层 + 六域)

每次合并同时审查功能与性能;基线只能由通过了自身层级的合并更新,回归阻塞合并直至修复或带数字书面论证。流程细节见参与开发 §3。

层级适用要求
Tier 1所有内核改动一次安静 syscost 启动:census 带内、tick ≥99.5/s、零新增 panic/OOM 类、系统调用量 ±10%、关键单次平均 ±20% 或更优
Tier 2热路径:mm/ sched/ fs/ ipc/ binder/ timer/ arch trap加一次 pbench 启动:P1–P7 中位数 ±20% 内或更优
Tier 3分配器或 IRQ 路径加 IF=0 中断关闭份额实测(EFLAGS 对探针 if0 v3,官方测量非代理)

六大看护域

域守护指标(现行带)
内存分配 / 回收small_alloc 全局类锁分段 ≤25M/次启动(实测 19.7M,最新板 6.0M)、REST 占比 ≤10%(现行 0.1–1.2%)、标准启动无回收慢路径浮现
调度GRQ 平均持锁门带 1200–7320 ns(实测 2786 ns @ n=6.3M,−48%)、census TERM 8±2 / REFUSED 32±4、P2 ±20%、futex 唤醒→运行 quiet 7.5 µs ±20%
文件系统热路径P6 行 ±20%(stat 71 / openclose 156 / append 77 / mkdrmdir 2760 / unlink 808 / write_fsync 14200 µs)、buffer cache 命中率 99.1% ≥ 基线、无新同步写类

总原则:任何可能影响性能的子系统都必须处于门禁测量范围之内 —— 如果现有工具测不了它,应为其新增 debug 观测工具(默认关闭)。测量是变更的组成部分,而非事后补充。

§9优化队列(开放差距,按优先序)

  • lat_syscall open 1.82× / stat 1.32×:路径解析尾部分解(campaign 已落 open 累计 −15.2%、stat −4.6%,继续攻)。
  • lat_proc fork 1.11×:retire batch-park 在途。
  • lat_syscall null 1.17× / write 1.10×:入口地板与 fill/copy 尾;write 距持平 6 ns。
  • Geekbench 单核余差复核:文本压缩 94% / 导航 81% / PDF 85% / Clang 88% / 人脸 87% 等待隔离复跑(AES-XTS 已根因修复,105–106%)。
  • 网络族:bw_tcp TIMEOUT / lat_connect 14–16 ms —— 调度 stale-claim 拒绝 accept server/worker 唤醒(WAKE-HEAL-SKIP ×39);修复后才能取得 TCP 吞吐读数。
  • pbench 主线堆问题:0d7993b6 之后 pbench 探针在 musl malloc get_meta 确定性死亡(疑似 scribble 家族),pbench Tier-2 腿暂停直到定位修复;lmbench 各行不受影响。
  • 补测队列:Geekbench 的同机 KVM Linux 对照;页缓存命中率绝对值、PCP 水位、binder 吞吐专项。

§10debug 测量工具链

  • syscost:启动普查(系统调用量、census 计数、tick 率、每操作均值)—— Tier 1 的采集器。
  • pbench(test/pbench.c):P1–P7 七组微基准探针 —— Tier 2 的采集器。
  • census / wakewatch:调度搁浅普查与唤醒→运行延迟取证(1024 槽旁表 + pick-skip 原因旁表)。
  • if0 v3:EFLAGS 对探针,官方 IF=0 份额与关中断段测量(已上 main,不再用 tick-mode 代理)。
  • fsw / mmprof 计数器:fs 同步写类、内存记账核对(OOM forensics)。
  • run/perf-gate.sh:门禁自动化(anchor JSON + Tier 调度 + 带判定)。
  • 统一 tracepoint 框架:51 事件/16 组,tracefs 逐字节对齐,启用价 +13–19 ns/记录(详见架构栏目可观测性)。
