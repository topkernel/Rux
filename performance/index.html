性能测试

结论先行,数据随后:与 Linux 同机同加速(QEMU q35 + KVM)对照 · 数据截至 2026-11-16 · 基线文件 docs/development/perf-gate-baseline.md

§1结论:与 Linux 相比领先多少、落后多少

本页所有与 Linux 的对照均为同机同加速:同一宿主(9950X)、同一 QEMU q35 + KVM(-accel kvm -cpu host)、同一镜像形状、同一静态基准二进制。不含任何裸机对照。

📏lmbench 同机对照:21 项中 14 项领先/持平、7 项落后

领先:lat_pipe 4.6×、lat_ctx 2P 4.0–4.5×、lat_ctx 8P 3.6×、bw_pipe 3.7×、lat_sem 2.9×、bw_unix 2.1×、lat_unix 1.4×、fstat 1.3×;bcopy/bzero/mem_rd/usleep 持平偏领先,bw_file_rd 快于计时器粒度。

落后(Rux/Linux):open 1.92×、read_cached 1.84×、stat 1.28×、write 1.06×;null 已到持平(0.97×);fork/exec 0.75–0.79×(领先)。存储与实时路径见下方对照。

领先最高 4.6× · 落后最大 2.5× · 数据见 lmbench 页

⚡存储与实时路径对照:相位探针归因 + 参考形态改造

存储 I/O 用两侧同机对账(共享 tracefs 时间线+相位括号+双方 perf)归因,再按参考内核实现形态改造:fsync 路径重造(未写盘区成批转换+邻接合并、每 inode 脏块笔记 O(dirty) 扫描、inode 表块搭同一刷写窗)——0.30× 到领先 ~1.24×;同步等待先有界轮询后睡眠(4k 随机写 0.97×、随机读写 0.96×、随机读 0.90×,平价带);直读物理连续段批量提交(1M 顺序读 226× 落后到 0.62×);缓冲写用户页直拷入帧(0.94×,rig 地板:冷帧 RFO 两侧共付);目录增量填充(getdents 领先 1.95×);close 条件引用获取+readahead 状态内嵌(openclose 1.59×、read_cached 1.66×,剩余主导=open 侧路径游走)。实时:定时器到期改在硬中断顶部派发(rt_wakesys 3.3 µs 持平)、PI futex 参考形态(pi_stress 132,074 反转)、cyclictest FIFO 平均 104→69 µs(最大 263,同机交错重银行中)。

逐项数据见 fio 页 与 rt-tests 页 · 方法与证据 docs/test/perf-campaign-2026-11-17.md

🏁Geekbench 5:单核 2440 / 多核 7709(历史最佳)

单核总分 2440 vs 2165(113%)、多核总分 7709 vs 7027(110%),best-of-runs 口径(gb-opt 轮,2026-11-15)。2026-11-04 完整捕获的逐项分布:多核 8 领先 / 5 持平 / 8 落后,单核 13 领先 / 3 持平 / 5 落后。

逐项数据见 Geekbench 页 · 机位注明:Linux 侧为宿主 4-CPU 钉核(taskset,拓扑对齐)
差距结构:领先面覆盖调度/唤醒(上下文切换、管道、信号量)、IPC 带宽(unix、pipe)与内存带宽;落后面集中在系统调用入口与路径解析(null/read/write/stat/open 1.2–2.5×)。历史 campaign 在旧参考窗口下曾把 fork/exec 记入持平带,2026-11-16 同 rig 参考列重测后回到 1.08–1.19× 带(参考内核切换族对测量窗口敏感,比值只在同会话内有意义)。campaign 随役修复的 5 个正确性 bug 见 §2 表后清单。

§3方法与 rig

  • 同机同加速:两侧同一宿主、同一 QEMU q35 + KVM(-accel kvm -cpu host)、同一 Ubuntu rootfs 形状、同一静态基准二进制;每启动一个用例(串口与长基准并发打印,单用例单次启动是唯一干净采集),runner 为 PID 1,35 秒 in-guest 预算(特殊用例单独注明)。
  • 类内可比铁律:debug 与 release-strong 不可跨类比(strong 在下限类指标低 10–30×);TCG 与 KVM 不可跨类比。
  • 锚溯源:锚只读 Rux 自身中位 —— Linux 列永远不进 Rux 门锚(leg 32 曾发现四格误抄自 Linux 列,已纠错并留档)。

§4合并门性能维度(三层 + 六域)

每次合并同时审查功能与性能;基线只能由通过了自身层级的合并更新,回归阻塞合并直至修复或带数字书面论证。流程细节见参与开发 §3。

层级适用要求
Tier 1所有内核改动一次安静 syscost 启动:census 带内、tick ≥99.5/s、零新增 panic/OOM 类、系统调用量 ±10%、关键单次平均 ±20% 或更优
Tier 2热路径:mm/ sched/ fs/ ipc/ binder/ timer/ arch trap加一次 pbench 启动:P1–P7 中位数 ±20% 内或更优
Tier 3分配器或 IRQ 路径加 IF=0 中断关闭份额实测(EFLAGS 对探针 if0 v3,官方测量非代理)

总原则:任何可能影响性能的子系统都必须处于门禁测量范围之内 —— 如果现有工具测不了它,应为其新增 debug 观测工具(默认关闭)。测量是变更的组成部分,而非事后补充。

§6优化队列(开放差距,按优先序)

  • COW 缺页跨 CPU shootdown:SMP-8 下 +58%(18.42 µs)的诚实缺口,影响 fork 密集服务图 —— 下一主攻方向。
  • lat_syscall open 1.61× / stat 1.32×:open 尾部(memo 命中 80–90 ns + fd 装配);stat 尾部 v3 因 call_rcu 契约已修而解锁重试。
  • lat_syscall null 1.18× / write 1.14×:入口地板;null 的 2× 已论证为两侧共享的 syscall RTT 物理下限,目标收敛到持平;write 距持平 6 ns。
  • Geekbench 单核余差复核:文本压缩 94% / 导航 81% / PDF 85% / Clang 88% / 人脸 87% 等待隔离复跑(AES-XTS 已根因修复,105–106%;单核 best-of-runs 2440 = 113%)。
  • 网络族:bw_tcp TIMEOUT / lat_connect 14–16 ms —— 调度 stale-claim 拒绝 accept server/worker 唤醒(WAKE-HEAL-SKIP ×39);修复后才能取得 TCP 吞吐读数。
  • 补测队列:fio 吞吐基准(同机 Linux 对照,direct=1 绕页缓存);Geekbench 的同机 KVM Linux 对照;页缓存命中率绝对值、PCP 水位、binder 吞吐专项。

§7debug 测量工具链

  • syscost:启动普查(系统调用量、census 计数、tick 率、每操作均值)—— Tier 1 的采集器。
  • pbench(test/pbench.c):P1–P7 七组微基准探针 —— Tier 2 的采集器。
  • census / wakewatch:调度停滞普查(WAKE-STRANDED)与唤醒→运行延迟取证(1024 槽旁表 + pick-skip 原因旁表)。
  • if0 v3:EFLAGS 对探针,官方 IF=0 份额与关中断段测量(已上 main,不再用 tick-mode 代理)。
  • fsw / mmprof 计数器:fs 同步写类、内存记账核对(OOM forensics)。
  • run/perf-gate.sh:门禁自动化(anchor JSON + Tier 调度 + 带判定)。
  • 统一 tracepoint 框架:69 事件/17 组,tracefs 逐字节对齐,启用价 +13–19 ns/记录(详见架构栏目可观测性)。
