性能测试

合并门性能维度 + 完整基准面板 + 已落地战役史 + 优化队列 —— 基线文件 docs/development/perf-gate-baseline.md,数据截至 2026-11-06

§1方法与 rig

  • 公平对比规则:比较两个内核时,两侧必须使用相同加速器。与 Linux 的对照分两列 —— Linux 裸机(native,不付虚拟化税)与 Linux 同机 KVM(同 rig,权威口径);rig-divergent 行以同机 KVM 对为准,另有安静窗复测。
  • 每靴一例:串口会与长基准并发打印,单用例单靴是唯一干净采集;runner 为 PID 1、35 秒 in-guest 预算(特殊用例外)。
  • 负载窗纪律:宿主 load ≥7 的读数作废重测;只比中位数(p99 由宿主噪声主导)。
  • 类内可比铁律:debug 与 release-strong 不可跨类比(strong 在地板族低 10–30×);TCG 与 KVM 不可跨类比(TCG p2 是负载人质:同内核 load 5–6 读 28.151 µs,KVM 三板 ±1%)。
  • 锚溯源:锚只读 Rux 自身中位 —— 参考列永远不进 Rux 门锚(leg 32 曾发现四格误抄自 Linux 列,已纠错并留档)。

§2合并门性能维度(三层 + 六域)

每次合并同时审查功能与性能;基线只能由通过了自身层级的合并更新,回归阻塞合并直至修复或带数字书面论证。流程细节见参与开发 §3。

层级适用要求
Tier 1所有内核改动一次安静 syscost 启动:census 带内、tick ≥99.5/s、零新增 panic/OOM 类、系统调用量 ±10%、关键单次平均 ±20% 或更优
Tier 2热路径:mm/ sched/ fs/ ipc/ binder/ timer/ arch trap加一次 pbench 启动:P1–P7 中位数 ±20% 内或更优
Tier 3分配器或 IRQ 路径加 IF=0 中断关闭份额实测(EFLAGS 对探针 if0 v3,官方测量非代理)

公平对比规则:比较两侧必须同加速。Linux 列同时给出裸机(native,不付虚拟化税)与同机 KVM 两列;rig-divergent 行(lat_pipe / lat_ctx / lat_proc)以同机 KVM 对为权威。虚拟化税的分布本身就是结论:系统调用行几乎无税(0.88–1.06×,guest 自带 syscall 入口不 vmexit);税集中在跨 vCPU 唤醒 IPI(lat_pipe 4.85×、lat_ctx 7.37×)与页表/TLB 工作(lat_proc 1.52–1.63×)。Rux 的单全局队列唤醒路径不制造跨核重调度风暴,几乎不吃这个税 —— quiet 窗 lat_ctx 0.73 µs 快于裸机 Linux 的 0.91 µs。

§8优化队列(开放差距,按优先序)

  • lat_pagefault 6.45× —— 缺页路径是当前最大单项差距,优化队列头部。
  • bw_tcp TIMEOUT / lat_connect 165× —— 同根:调度 stale-claim 拒绝 accept server/worker 唤醒(WAKE-HEAL-SKIP ×39);连接与数据路径本身已通。
  • read/write 系统调用 1.6× 族 —— 差距在 fill/copy 尾部(SMAP AC 括号)与系统调用入口地板(null 同机对 1.31×),fd 查找已不是瓶颈。
  • futex 唤醒→运行:"既有在跑任务"场景 ~10 ms(tick 量化,已入账成本;quiet 7.5 µs 带内);p4 fork 族 TCG 类开放回归按 KVM 锚重裁中。
  • 未测面:页缓存命中率绝对值、PCP 水位、TCP 吞吐(bw_tcp 修复前无法测)、binder 吞吐/延迟专项、GRQ hold 分段分解对照。

§9debug 测量工具链

  • syscost:启动普查(系统调用量、census 计数、tick 率、每操作均值)—— Tier 1 的采集器。
  • pbench(test/pbench.c):P1–P7 七组微基准探针 —— Tier 2 的采集器。
  • census / wakewatch:调度搁浅普查与唤醒→运行延迟取证(1024 槽旁表 + pick-skip 原因旁表)。
  • if0 v3:EFLAGS 对探针,官方 IF=0 份额与关中断段测量(已上 main,不再用 tick-mode 代理)。
  • fsw / mmprof 计数器:fs 同步写类、内存记账对账(OOM forensics)。
  • run/perf-gate.sh:门禁自动化(anchor JSON + Tier 调度 + 带判定)。
  • 统一 tracepoint 框架:51 事件/16 组,tracefs 逐字节对齐,启用价 +13–19 ns/记录(详见架构栏目可观测性)。
