rt-tests(cyclictest / hackbench / pi_stress)

实时延迟与调度压力的性能对照(同机同镜像同二进制),无数据项即失败 · 测试平台与方法

§1数据(同机同镜像同二进制对照)

两侧使用同一镜像、同一 rt-tests v2.11 静态二进制、同一参数,Rux(main release)与 Linux(同镜像 guest 内核 7.0.0-38)同机交替测试(每形态 3 轮)。cyclictest:30 s 窗、1000 µs 间隔、mlockall;hackbench:消息传递吞吐(秒,越低越好)。cyclictest 行取干净轮数值,负载轮的最大值两侧共受宿主负载波影响,行内如实标注。

注:SCHED_OTHER 行领先来自 CFS 唤醒路径(抢占默认开后同机交替测试)。FIFO 行为干净轮口径:最小值每个干净轮都胜,干净轮最大值优 10×(207 vs 2185);负载轮 2.2–2.4 ms 为两侧共有的宿主负载波;平均残差=自身装填/到期/拾取/返回成本(已裁定无虚拟化共付地板),路径 104→46→14–19(硬中断到期+余量豁免+唤醒定向阶梯+装填瘦身)。rt_wakesys 在定时器到期改到硬中断顶部派发后与 Linux 持平。hackbench 为 3 轮取中位数(唤醒落位定向后)。pi_stress:3 深嵌套链最差顶等待 374 µs,glibc PI 互斥三例=提升/进程内死亡/跨进程 SIGKILL 恢复;数值优先级沿链传播(rt_mutex_adjust_prio_chain 形状),属主死亡返回 0 并在字内锁存 OWNER_DIED(曾返回 -EOWNERDEAD 被 glibc 判致命);SleepMutex rt 模式覆盖三把 RT 相关睡眠锁,不做全树自旋锁转换(D-26)。无数据项即失败:hackbench inet ≥2 组在 Rux 无数字(回环非阻塞 connect 停滞,网络工作分支已记录在案)。hackbench 旧行的 4.7–9.6× 差距为 debug 构建时代的读数;现行数字为 release 构建同机交替测试,3 轮取中位数收尾中,收尾后行内数值随之刷新。本表以最新一轮双侧读数为准。

§2测试平台与方法

  • 对照组:与 fio 页同一对内核、同一镜像(reflink)、同一次注入的二进制(源码 tar 包入 git,musl 静态构建;含 numa shim 与 musl sched_* ENOSYS 桩覆写)。
  • 协议:每侧一次启动顺序执行全部项(qsrun cmds 协议);cyclictest 直出统计行,hackbench 直出耗时行。

§3工具链

  • rt-tests v2.11 原版源码入库;构建脚本 userspace/tests/rttests/build-x86.sh;schedprobe(随启动注入)验证原生 sched_* 系统调用面。
  • 扩展:test/qrtests/run-suite-x86.sh "60 cyclictest -D 30 -i 1000 -m";直方图模式(-h 落盘)与 Linux 列扩展在补测队列。
