## 1. Executive summary

Round 3 review statistics (after dedup):

| Severity | Count | Description |
|---|---|---|
| Critical | 34 | Hangs/panics, silent data corruption, privilege escalation, physical memory UAF |
| High | ~110 | User-visible incorrect behavior, probabilistic hangs/UAF, POSIX/ABI violations |
| Medium | ~185 | Bounds/semantic deviations, missing permission checks, race windows |
| Low | ~135 | Details, performance, consistency |

Six major themes (by risk concentration):

1. **Low-level context switching and exception handling are unreliable** (ARCH-C1/C2) — the suspected root cause of all "probabilistic" symptoms.
2. **User input reaching kernel core paths lacks defenses** (allocation sizes, ELF bounds, raw user pointers, fd types) — one-step hang/privilege escalation.
3. **The network stack has never actually worked in either RX or TX** (NET-C1/C2/C3/C4) — the previous rounds' "fixed" claims were never verified with real RX/TX.
4. **Routine ext4 operations silently destroy the disk** (EXT4-C2/C3/C4) + systematic page-lifecycle leaks (munmap without put_page, swap slot UAF).
5. **Wait/wakeup primitives broken across the board** (futex >8 not woken, semop semantics inverted, timeouts never taking effect, vfork lost wakeup) — multithreaded and shell scenario hangs.
6. **Test and documentation credibility** (SPIN LTL unverified, unit tests without CI, fake tests, docs like kernel-lock.md describing removed mechanisms).

Suggested cadence: **Wave 1 first** (within 1 week, stop the bleeding); Wave 2 immediately after (security and data-integrity baseline); Wave 3/4 restore network and driver usability; Wave 5–7 advance semantics by module; Wave 8/9 run governance in parallel with each wave. Total ~**35–50 person-days**.

## 12. Dependencies and masking relationships (must be noted when fixing)

1. **ARCH-C1 (the exception table) is a prerequisite for the 1.6 raw-dereference fix**: after the exception-table fix, a missed raw dereference downgrades from "whole-machine hang" to EFAULT, but all still need switching to copy_from_user.
2. **The DRIV-C1/C2 fixes will expose** DRIV-H4 (async reads necessarily EIO) and DRIV-M1 (MTU=1) — must be fixed in the same batch.
3. **The NET known limitations (F10-06/07/22/24/29/33) are all masked by NET-C1/C2/C3/C4**: after the C series is fixed, re-evaluate whether the known-limitation list still holds (F10-06/33 expected to dissolve; F10-22/29 need real implementation).
4. **The ARCH-C2 fix may change the "probabilistic" symptom baseline**: after the fix, fully regress SMP boot and long LTP runs to see whether residual probabilistic issues remain (possibly manifestations of IPC-C2/H4-type concurrency defects).
5. **EXT4-H10 (the global lock) should land before EXT4-C2/C4**: eliminate concurrency first, then change the extent logic, to avoid introducing new races right after the change.
6. **PROC-P04 (the deferred-notify regression) and PROC-P02 (vfork) were both introduced in recent commits**: when fixing, verify against the git history with revert comparisons, confirming the lost-wakeup 994b306 originally meant to fix isn't broken.

## 14. Long-term mechanism suggestions (preventing recurrence)

1. **Exception-table/assembly-level CI validation**: the build script checks .ex_table entries one-to-one against disassembled memory-access instructions (auto-intercepting ARCH-C1-class defects).
2. **End-to-end smoke**: bring "real RX/TX" (network echo), "real COW" (fork+write), "real blocking" (pipe/sem/futex timeouts) into smoke — this round proved that unit tests testing only constants give the illusion of "fixed".
3. **Fuzzing entry points**: hook simple fuzzers (bit flips + boundary-value generation) into the three parsers — ELF headers, ext4 images, DTB — any panic is a failure.
4. **Auto-generated numbers**: test counts/line counts/syscall counts generated by scripts in CI and checked against the docs, ending multi-version drift.
5. **KNOWN LIMITATION re-review**: after each round of fixes, re-review the known-limitation list; masked items (like this round's NET series) re-graded promptly.
