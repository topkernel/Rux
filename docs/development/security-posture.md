# Kernel Security Posture Ledger

Living artifact of the security review track (user directive,
2026-10-29: security hardening for a monolithic kernel). Every
isolation/privilege surface carries a row: current state, the
reference kernel's behavior, a gap class, and the test that guards
regressions. Generated by `scripts/security_posture.py` — edit the
ROWS table there, not this file. `--check` fails on drift.

**Framing (user directive):** Rux is a MONOLITHIC kernel — there is
no microkernel message boundary to hide behind. The isolation story
IS the syscall boundary (uaccess + entry validation) plus the
privilege model (capabilities + seccomp + exec transitions). Every
row below is one of those two things, or feeds them (W^X, KASLR,
and leak hygiene protect the boundary's enforcement machinery).

## The ledger

### user/kernel isolation

#### syscall entry validation — OK

- **State:** Every syscall enters one dispatch (syscall/dispatch.rs, 1214 lines); numbers are per-arch (riscv64 native; x86_64 translated in syscall/x86_compat.rs with explicit no-fallthrough for unknown x86 numbers — several x86 numbers collide with DIFFERENT generic syscalls).
- **Reference:** Reference: do_syscall_64 -> syscall table indexed by nr; unknown nr returns -ENOSYS.
- **Gap class:** ok
- **Regression guard:** LTP syscall family (unknown-nr rows); dispatch unit rows

#### uaccess: bounds-checked copies — OK

- **State:** Every accessor (get_user/put_user/copy_from_user/copy_to_user/clear_user/strncpy_from_user/strnlen_user) routes through arch extable copy cores: riscv64 SUM-bracketed asm with per-byte and word paths (arch/riscv64/uaccess.S), x86_64 restartable rep-movsb with __ex_table entries (arch/x86_64/uaccess.rs); access_ok(addr, n) checks [addr, addr+n) <= USER_END on every accessor; a fault returns short/EFAULT, never panics (LTP x86-r2 N1 evidence: 37 EFAULT-family tests pass through the fixup). ~150 call sites across syscall/*.
- **Reference:** Reference: same shape (extable + access_ok).
- **Gap class:** ok
- **Regression guard:** LTP EFAULT family; copy stratagem unit rows

#### uaccess TOCTOU on user pointers — PROJECT

- **State:** No wholesale audit exists. Known-good pattern: args copied ONCE into kernel memory at the ladder head (exec argv/envp via get_user loop into String; sock_fprog copied wholesale). Known-risk pattern to audit: syscalls that copy a struct containing embedded user POINTERS and later deref those pointers with the user's remaining lifetime (iovec chains, msghdr, sigaction handlers, clone args, bpf_attr — the latter ENOSYS). No kernel thread ever runs with a user mm that can be concurrently mutated by a sibling during the copy window except CLONE_VM threads sharing the mm.
- **Reference:** Reference: copy_struct_from_user once + user_access_begin/end regions; unsafe_user_pointer pointers never live across copies.
- **Gap class:** project
- **Regression guard:** New: LTP io_uring/msg fault-injection rows + a grep audit pass in this lane's review coverage (per-file marks)

#### SMAP/SMEP (x86_64) — PROJECT

- **State:** NOT enabled. uaccess.rs header states it; CR0.WP IS enabled from earliest boot (F1b fix, boot.rs:95) so supervisor writes to read-only PTEs fault — half the protection exists. SMEP equivalent on riscv64 is architectural (U-mode cannot execute supervisor pages; sstatus.SUM=0 keeps user pages unreadable in S-mode, SUM convergence review SEC).
- **Reference:** Reference: CR4.SMAP+SMEP set at boot; stac/clac around uaccess.
- **Gap class:** project
- **Regression guard:** Boot tripwire + LTP full-family sweep (any missed raw user deref panics at runtime)

#### riscv64 SUM discipline — OK

- **State:** sstatus.SUM deliberately kept 0 (exec entry comment, review SEC): kernel reaches user memory only via uaccess exception paths. sret to U-mode with SUM=0 is the ABI.
- **Reference:** Reference: equivalent (no SUM on most ports; SMAP-like via PMP).
- **Gap class:** ok
- **Regression guard:** exec entry unit rows; any SUM=1 boot print would be a regression

### privilege model

#### capability set breadth (41 caps) — PROJECT

- **State:** All 41 CAP_* constants present with exact Linux UAPI numbering (security/capability.rs); Cap(u64) with valid-mask enforcement; capget/capset ABI via lo/hi halves. Enforcement coverage is PARTIAL: checked at setuid/setgid exec transition (cap drop rules), kill permission, seccomp attach, mount/umount, chroot, mknod, syslog, reboot, clock_set, iopl/ioperm (x86), IPC owner override. NOT enforced (no-op or absent): CAP_NET_ADMIN/NET_RAW class gates (raw socket create unprivileged — audit pending), CAP_IPC_LOCK (mlock unbounded), CAP_SYS_RESOURCE (rlimits bypass unprivileged?).
- **Reference:** Reference: every capable() site enumerated in Documentation/security; ~120 check sites.
- **Gap class:** project
- **Regression guard:** LTP capability family (capset01-08, execve cap drops); new: per-syscall capability audit pass in this lane

#### setuid/setgid exec transitions — OK

- **State:** Implemented with rollback-on-failed-load (cred snapshot restored); AT_SECURE=1 exactly when ids change (root AT_SECURE false-positive fixed in session 1); ambient caps cleared on exec; x-bit required for setuid to apply; kernel-side LD_* scrub (D-9).
- **Reference:** Reference: bprm_fill_uid + cap_bset intersection rules.
- **Gap class:** ok
- **Regression guard:** LTP execve/setuid family; shebang + secure-exec unit rows

#### no_new_privs (PR_SET_NO_NEW_PRIVS) — OK

- **State:** LANDED (security session 2, branch feature/security-review): prctl 39/40 implemented with the reference one-way shapes (arg2 must be exactly 1, no clear exists; GET rejects nonzero args), sticky across fork and exec, gates unprivileged seccomp attach, and exec ignores setuid/setgid bits while set. LTP prctl02 PASS post-fix.
- **Reference:** Reference: prctl(39) sets per-thread flag; inherited across fork and exec; exec refuses privilege GAIN when set (EPERM); makes unprivileged seccomp attach legal.
- **Gap class:** ok
- **Regression guard:** 10 unit rows (seccomp-nnp group) + LTP prctl02/prctl03

#### seccomp (engine) — OK

- **State:** REAL and substantially complete (U1c landed, coordinator's 'likely no engine' was stale): classic-BPF subset interpreter (LD|W|ABS/IMM, JMP|JEQ/JGT/JGE/JSET|K, RET|K; max 4096 insns; oob-load and fall-off-end kill), gate called from BOTH trap paths BEFORE dispatch, STRICT and FILTER modes, kill actions queue SIGKILL, fork inheritance (fork.rs seccomp_dup).
- **Reference:** Reference: full classic BPF + cBPF-to-eBPF, filter STACKING, TSYNC, RET_TRACE, USER_NOTIF, SECCOMP_RET_KILL_PROCESS vs KILL_THREAD distinction, filter-LOG.
- **Gap class:** ok
- **Regression guard:** LTP prctl02/04 + the seccomp-nnp unit group (STRICT per-arch row; prctl04 rerun is merge debt behind the main panic fix)

#### seccomp FIXED (was: STRICT_ALLOWED riscv64-only on both arches) — QUICK

- **State:** syscall/process.rs:4528 const STRICT_ALLOWED = [63 read, 64 write, 93 exit, 94 exit_group, 139 rt_sigreturn] with no arch gate; the x86_64 trap gate passes the RAW x86_64 number (regs.rax, BEFORE x86_compat translation). Consequence on x86_64: native read(0)/write(1)/exit(60)/exit_group(231)/rt_sigreturn(15) are all KILLED; uname(63) is ALLOWED as if it were read. A task entering STRICT on x86_64 dies on its first read. FILTER mode is incidentally CORRECT on x86_64 (native numbers + AUDIT_ARCH token = 0xC000003E even though the constant is misnamed AUDIT_ARCH_RISCV64).
- **Reference:** Reference: strict mode allows read/write/exit/exit_group/sigreturn per the RUNNING arch's numbers.
- **Gap class:** quick
- **Regression guard:** New unit rows (per-arch allowed sets); a STRICT-mode smoke on x86

#### seccomp divergence: single filter, no TSYNC/TRACE/NOTIF — ACCEPTED

- **State:** One filter per task, new replaces old (documented in code); TSYNC/LOG/SPEC_ALLOW/TSYNC_ESRCH flag bits accepted-and-ignored (TSYNC semantics NOT applied despite being in the accept mask — a thread group calling TSYNC gets the filter only on the caller); KILL_PROCESS and KILL_THREAD both kill the current task (seccomp_kill queues SIGKILL on current only).
- **Reference:** Reference: filters stack (all evaluated, most restrictive wins); TSYNC applies to all sharing threads with E2BIG/ESRCH shapes; KILL_PROCESS kills the thread group.
- **Gap class:** accepted
- **Regression guard:** documented divergence — register in design-divergences.md when the stacking work lands. Kill SIGNAL identity now matches the reference (SIGSYS, force semantics — session 2; was SIGKILL)

### MAC

#### SELinux enforcement depth — PROJECT

- **State:** LABEL-CARRYING ONLY, permissive by construction (fs/selinuxfs.rs): selinuxfs is a minimal libselinux-compat mount (enforce reads 0, load accepts-and-discards, context node world-rw for samgr's CheckPerm, static selinux_status page). No policy is parsed, no AVC decisions are made, no xattr contexts are read from inodes. The OH image's SELinux userspace boots and gates services through this compat surface; nothing is enforced.
- **Reference:** Reference: policy load, SID table, AVC with permissive/enforce modes, xattr label fetch on inodes.
- **Gap class:** project
- **Regression guard:** documented: this IS the registered state; any future policy engine starts from this ledger row

### memory safety

#### kernel text/rodata W^X — PROJECT

- **State:** NOT enforced. riscv64: whole kernel image mapped V|R|W|X (both identity and virtual, mmu_init.rs kernel_flags). x86_64: image mapped P|RW without NX (executable by absence of NX bit). No post-boot RO/ROX tightening pass exists. No kernel module loader (no runtime text allocation). No JIT in-tree today (OH ArkTS runs in USERSPACE and manages its own W^X via mprotect).
- **Reference:** Reference: mark_rodata_ro() at init, NX on data, CONFIG_STRICT_KERNEL_RWX.
- **Gap class:** project
- **Regression guard:** New tripwire: page-table walk asserting text pages RO after init (gated dfx knob), any W+X page print

### information leaks

#### /proc/kallsyms addresses — QUICK

- **State:** REAL ADDRESSES to every reader (fs/procfs/kallsyms.rs header says so: 'Linux masks with kptr_restrict — Rux has no such knob'). Defeats KASLR by reading one file (and KASLR is off anyway).
- **Reference:** Reference: kptr_restrict=1 zeroes addresses for unprivileged readers; kallsyms shows 0000000000000000.
- **Gap class:** quick
- **Regression guard:** grep test: unprivileged read of /proc/kallsyms yields zeros when the knob lands

#### KASLR — PROJECT

- **State:** DISABLED (memory_layout.rs KernelMapping.kaslr_offset: '0 if KASLR disabled'; boot.S loads fixed KERNEL_ENTRY). Field and plumbing exist; no entropy source is wired at boot.
- **Reference:** Reference: CONFIG_RANDOMIZE_BASE, offset from RDRAND/trng.
- **Gap class:** project
- **Regression guard:** boot print of kaslr_offset twice must differ; PMP/phys window constraints on riscv64 make this a design task

#### kernel pointers in other /proc nodes — QUICK

- **State:** NOT audited. /proc/[pid]/stat has kstkeip/kstkesp fields (pid.rs) — check they are 0; /proc/[pid]/wchan, stack (dfx) unaudited. DFX files under debugfs are root-gated by DAC only.
- **Reference:** Reference: kptr_restrict governs all of these.
- **Gap class:** quick
- **Regression guard:** audit pass over procfs/pid.rs generators in this lane
