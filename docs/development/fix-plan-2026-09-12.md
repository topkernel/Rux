## 1. 执行摘要

第三轮审查统计（去重后）：

| 严重级别 | 数量 | 说明 |
|---|---|---|
| Critical | 34 | 挂死/panic、静默数据损坏、提权、物理内存 UAF |
| High | ~110 | 用户可见错误行为、概率性挂死/UAF、POSIX/ABI 违反 |
| Medium | ~185 | 边界/语义偏差、权限缺失、竞态窗口 |
| Low | ~135 | 细节、性能、一致性 |

六大主题（按风险集中度）：

1. **底层上下文切换与异常处理不可靠**（ARCH-C1/C2）——所有"概率性"症状的疑似根因。
2. **用户输入到达内核核心路径缺乏防御**（分配大小、ELF 边界、裸用户指针、fd 类型）——一步挂死/提权。
3. **网络栈收发双向从未真正工作**（NET-C1/C2/C3/C4）——前两轮"已修复"未经真实收发验证。
4. **ext4 常规操作静默毁盘**（EXT4-C2/C3/C4）+ 页生命周期系统性泄漏（munmap 不 put_page、swap slot UAF）。
5. **等待/唤醒原语大面积失效**（futex >8 不唤醒、semop 语义反转、超时永不生效、vfork 丢唤醒）——多线程与 shell 场景挂死。
6. **测试与文档可信度**（SPIN LTL 未验证、单测无 CI、假测试、kernel-lock.md 等文档描述已删除机制）。

建议节奏：**Wave 1 先行**（1 周内，止血）；Wave 2 紧随（安全与数据完整性底线）；Wave 3/4 恢复网络与驱动可用性；Wave 5–7 按模块推进语义；Wave 8/9 与各波并行开展治理。总量约 **35–50 人天**。

## 12. 依赖与掩盖关系（修复时必须注意）

1. **ARCH-C1（异常表）是 1.6 裸解引用修复的前置**：异常表修复后，漏改的裸解引用才从"整机挂死"降级为 EFAULT，仍需全部改 copy_from_user。
2. **DRIV-C1/C2 修复会暴露** DRIV-H4（async 读必 EIO）与 DRIV-M1（MTU=1）——必须同批修。
3. **NET 已知限制（F10-06/07/22/24/29/33）全部被 NET-C1/C2/C3/C4 掩盖**：修完 C 系列后再评估已知限制清单是否仍成立（预计 F10-06/33 消解，F10-22/29 需真正实现）。
4. **ARCH-C2 修复可能改变"概率性"症状基线**：修复后请完整回归 SMP 启动、LTP 长跑，观察是否还有残留概率性问题（可能是 IPC-C2/H4 等并发缺陷的表现）。
5. **EXT4-H10（全局锁）建议在 EXT4-C2/C4 之前落地**：先消并发再改 extent 逻辑，避免改完又引入新竞态。
6. **PROC-P04（deferred notify 回归）与 PROC-P02（vfork）都在最近 commit 中引入**：修复时在 git 历史上 revert 对照验证，确认不破坏 994b306 原本要修的 lost-wakeup。

## 13. 每批次通用回归门禁

1. `make build && make build-release`（两种 profile）
2. `make test`（单测，配合 8.1 的 CI 化判定）
3. `make run` + smoke 15 项
4. 涉及 fs/ext4：e2fsck -f 校验测试后镜像
5. 涉及 net：loopback echo + slirp ping
6. 涉及 arch/sched：4 核 SMP 启动 + LTP 抽样长跑（重点观察历史"概率性"症状）
7. commit 规范沿用现有惯例：`fix(<scope>): <摘要> (Wave N)`，正文引用检视报告 ID（如 `Fixes ARCH-C1`），便于双向追溯。

## 14. 长期机制建议（防复发）

1. **异常表/汇编级 CI 校验**：构建脚本比对 .ex_table 表项与反汇编访存指令一一对应（ARCH-C1 类缺陷自动拦截）。
2. **端到端冒烟**：把"真实收发"（网络 echo）、"真实 COW"（fork+写）、"真实阻塞"（pipe/sem/futex 超时）纳入 smoke——本轮证明只测常量的单测会给 出"已修复"的假象。
3. **模糊测试入口**：ELF 头、ext4 镜像、DTB 三个解析器接入简易 fuzz（位翻转 + 边界值生成），任何 panic 即失败。
4. **数字自动生成**：测试数/代码行数/syscall 数由脚本在 CI 中生成并校对文档，杜绝多版本漂移。
5. **KNOWN LIMITATION 复审**：每轮修复后复审已知限制清单，被掩盖的项（如本轮 NET 系列）及时重新定级。
