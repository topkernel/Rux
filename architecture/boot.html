启动流程

三架构从固件握手到 init · 出处 docs/architecture/boot.md 与 arch/ 源码

§1riscv64

QEMU -kernel rux
  └─ OpenSBI(fw_dynamic)  M 模式
       └─ S 模式 _start    a0=hartid, a1=DTB, 其余 hart 停车
            ├─ 早设 stvec、建 tp(per-CPU 区)、建 Sv39 内核页表
            └─ boot hart 初始化全部子系统 → 其余 hart wfi 等 SMP_INIT_DONE
  • SBI 使用:PUT_CHAR / SHUTDOWN / HART_START(0x48534D)/ SEND_IPI(0x735049)。
  • 定时:Sstc 扩展直接写 stimecmp(免每 tick 一次 SBI ecall)。

§2x86_64(q35)

multiboot1 ELF → 64 位 stub → rust_main
  └─ SIPI trampoline 唤醒 AP
       ├─ bzImage 引导协议:同一镜像可在期待标准引导协议的 loader 处启动
       └─ bootstrap PML4 的低恒等窗在 boot 栈切换后立即 UNLINK(分歧 D-17)

§3aarch64(QEMU virt)

QEMU -M virt,gic-version=3 -kernel rux   # 裸 ELF,无引导协议
  └─ 内嵌完整 QEMU-virt DTB blob(build.rs 从 QEMU 导出)
       ├─ EL2 → EL1h:HCR_EL2=RW、中断全路由 EL1、双定时器使能、CPACR_EL1.FPEN
       └─ 早期 TTBR0 恒等窗(phys [0,2GB))在 SMP 启动后拆除
aarch64 必须带 -M virt,gic-version=3;cmdline 从内嵌 DTB 的 /chosen/bootargs 读取。

§4启动成功的串口标志

最小系统:OpenSBI 横幅 → Rux ASCII banner → 模块初始化表(console/trap/mm/sched/fs/driver/smp 全 [ok])→ init: loading /bin/sh → shell 提示符。

x86_64 Ubuntu:初始化完成 → 帧缓冲分辨率 → 登录界面就绪;4 vCPU MTTCG 下 boot-to-login 实测 ~4.5 s。

§5启动参数与镜像纪律

  • 典型内核命令行:root=/dev/vda rw init=/sbin/init console=ttyS0(+ 可选 debug= 旗标,riscv64/x86_64 有效;aarch64 因 DTB 指针被早期 EL2 跳板破坏而不可用,退回编译期 feature)。
  • 共享镜像一律 -snapshot + file.locking=off;不要为标准流程手写 QEMU 命令 —— 参数都在 Makefile 与既有驱动脚本里。
