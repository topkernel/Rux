启动流程

kernel/src/arch/*/ + main.rs · 三架构引导协议、早期内存、内核镜像布局、多核拉起、陷入/系统调用入口与设备地址纪律 · 依据:docs/architecture/boot.md、riscv64.md、aarch64.md、design-divergences.md(D-17/D-18)

§1启动不变量

三架构共享一组显式记录的启动不变量(boot.md):

  • 分配器前代码仅用静态 BSS 池 —— 每个早期阶段的数据结构在无堆条件下自洽;
  • boot CPU 独占全部早期初始化,次级核自旋于 release 标志直至调度器就绪;
  • init= 解析与 PID-1 契约位于 rust_main 末段 —— ltpscan 与 lmbench runner 本身即 PID-1 ELF。

通用启动序(全三端口):arch 早期引导(页表、串口)→ 内存初始化(memblock、zone、vmemmap、小对象分配器)→ 陷入/中断 → 调度器与 init 任务 → 驱动探测 → 挂载根 → 运行 init。

§2riscv64:OpenSBI M→S

  • 引导链:QEMU 载入 OpenSBI(fw_dynamic)于 M 态,移交 S 态内核于 _start(a0 = hartid,a1 = DTB 指针);boot.S:置栈、PC 相对清 BSS、构建蹦床页表(首 2MB 内核 VA→PA)再完整早期页表,启用 MMU 后跳 VA 进入 rust_main。
  • SMP 拉起:OpenSBI HSM 启动全部 hart;首个经 CAS 到达 init() 者为 boot hart,其余在 SMP_INIT_DONE 上 wfi 等待。
  • R87 次级核bring-up窗口(教训):次级核等待期曾以定时器已使能 + wfi 运行 —— BSP 尾段(fs 挂载、驱动、init 派生,随 -m 缩放)期间每个 tick 可经 irq_exit 抢占进入 __schedule(),而 PER_CPU[hart] 仍为全零槽位;零槽位引发 heal 链、hart 携 boot 栈执行入队任务、槽位争夺在上下文切换时簿记错误的 prev —— 混合上下文保存(一任务的寄存器写入另一任务的 thread 记录),爆点为"kill the idle task" KERNPANIC。修复 = 自旋等待 is_boot_complete(非 wfi —— QEMU 的 wfi 仅被已使能 pending 中断唤醒),PER_CPU[hart] 发布后才使能定时器/外部/软件中断;配套发现:boot.S 对每 hart 清零 sie 而 ipi::init 仅置 boot hart 的 SSIE —— 无 per-hart SSIE 时次级核全部 IPI 被屏蔽(resched/TLB/call-function 永久 pending;tick 量化 futex wake→run 9118 µs vs 同 hart 24 µs)。规则已登记:次级核在 per-CPU 状态完整初始化并进入 idle 循环前不得接收中断(与参考内核同规则)。
  • per-CPU 中断栈:每 CPU 16KB、16 字节对齐;内核态陷阱用之(用户陷阱用任务内核栈)。

§3x86_64:multiboot1 + bzImage 双协议

  • multiboot1 路径:QEMU -kernel ELF,32 位保护模式进入(eax = 0x2BADB002,ebx = multiboot 信息指针);boot.S 保存指针、构建早期页表(低恒等 + 高半内核映射)、启用 long mode;multiboot blob 位于低内存 —— 早期即整体拷贝入内核 BSS(内存映射、cmdline、引导器名),因 bootstrap 恒等映射在真实页表安装后即消亡。
  • bzImage 路径(Linux 引导协议头 + 16 位蹦床):16 位 → 保护模式(硬编码绝对远跳)→ 0x100000(32 位 boot stub)→ long mode → 内核;同镜像可在期望 Linux 引导协议的加载器下启动。
  • bootstrap 恒等映射的生命周期:bootstrap PML4 含低恒等窗(仅为 boot 栈服务);mm::init() 构建真实高半内核表并切换 CR3 后,PML4[0] 于栈切换后立即 UNLINK(drop_bootstrap_identity)—— 运行期不存在低恒等窗(D-17,§6)。
  • above-4G BAR:宿主桥可将 virtio 64 位 BAR 置于任意 above-4G 地址 —— 两个静态别名窗 + 动态 ioremap 竞技场(K1-BAR);ECAM 于 q35 MMCONFIG 0xb0000000;IOAPIC/LAPIC 映射于 2GB bootstrap 覆盖之上(走表分配新 PMD,不降级 bootstrap 叶)。

§4aarch64:无固件 ELF + 内嵌 DTB

  • 引导形态:QEMU -kernel 纯 ELF 无镜像协议 —— x0 无 DTB 指针,-append/-dtb 被忽略;内核将完整 QEMU-virt DTB 内嵌于 .rodata(符号 aarch64_virt_dtb,build.rs 于 .dtb 缺席时自 qemu-system-aarch64 -M virt,gic-version=3 -cpu cortex-a72 转储);cmdline 取内嵌 /chosen/bootargs。每次启动必须 -M virt,gic-version=3(默认 virt 为 GICv2,驱动与内嵌 DTB 均为 v3)。
  • 入口:EL2 → 降 EL1h(HCR_EL2 仅 RW;全部中断路由留 EL1;CNTHCTL 开双定时器;CPACR_EL1 FPEN 置位 —— 否则 NEON 陷阱)。
  • 恒等窗生命周期:TTBR0 恒等窗覆盖物理 [0,2GB),SMP 启动后拆除 —— cpu_started(n) ⇒ 核 n 不再需要低地址(次级核 stub 先装高 VA VBAR 再报告启动,该序使拆除合法);boot 核 TTBR0 停靠内核根 + 广播 vmalle1is 清缓存;低地址 usercopy 经例外表 fixup → −EFAULT。
  • 内存图:线性映射 phys P → PAGE_OFFSET + P;内核镜像 32MB 窗;内核侧 MMIO 别名于 VMALLOC_START(低窗覆盖物理 [0,1GB));第二窗映射 PCI ECAM(物理 0x40_1000_0000,256MB,跨 RAM 尺寸固定)。

§5内核镜像布局与静态预留

  • 链接期 ASSERT 守护窗口:riscv64 ASSERT(_end <= 0xffffffff81c00000, ...) —— 窗口经 LAYOUT-2..6 一路扩展(12→14→18→20→24→26→28MB;D-3 符号表 +3.1MB 曾要求窗口同步扩展);x86_64 ASSERT(__kernel_lma_end <= 0x28000000, ...)(40MB)—— 历史上 x86_64 无守护,镜像越窗后静默破坏启动(unreserved 活 .bss 尾)。
  • memblock 预留跟随真实镜像末端(2df7b612):静态 30MB 预留曾落后 31.4MB SMP8 镜像 368KB —— buddy 分发活 .bss,kernel_layout() 读出垃圾,全部 create_user_address_space 根页被拒,exec /init 报 ENOMEM(上游曾误诊为"ramfs ELF phdr 损坏",文件字节完好)。修法:reserve max(KERNEL_RESERVE_SIZE, kernel_image_phys_end())。
  • 数字型事故:KERNEL_RESERVE_SIZE 640MB→40MB 一位数笔误(fake-OOM 引擎 —— 351MB→951MB 虚假种子,16/16 启动零 OOM);riscv64 堆基曾置于镜像窗内 2MB(镜像 .bss 含 boot 栈增长后越过堆基,单测启动 panic)。rust_main_tail 布局守卫:镜像与堆基重叠即停机。
  • Kernel.toml 尺寸策略:kernel_heap_size = 1024MB(OH 语境:512MB 窗口曾坐至 ~513/524MiB,clone 堆预留门 <8MiB 触发,全部 pthread_create EAGAIN,FFRT 服务中止)。

§6陷入/系统调用入口与 uaccess

  • riscv64:PtRegs 288 字节 #[repr(C)](orig_a0 独立槽位,系统调用回滚用);sscratch/tp 交换协议判别陷阱来源(内核 = sscratch 0;用户 = sscratch 持任务指针),带早期启动回退;内核陷阱路径:per-CPU 中断栈选择(经 ti_cpu,嵌套则跳过)→ 288 字节 PtRegs → 保存 31 个 GPR → CSR 于寄存器后读取 → 获取内核大锁 amoswap.d.aq → 清 sscratch。用户陷阱出口:保存 ti_kernel_sp → 信号/重调度循环 → 恢复 sstatus/sepc/GPR → 释放锁 amoswap.d.rl → sc.d 清 LR/SC 保留 → 恢复 sscratch → fence → sret。
  • x86_64:STAR = (0x23<<48)|(0x08<<32) —— SYSCALL 进入 CS=0x08/SS=0x10,SYSRET64 返回 CS=0x33/SS=0x2b;FMASK = TF|IF|DF —— 系统调用以 IF=0 进入,handle_syscall 立即重开中断(参考同纪律:全程 IF=0 运行系统调用将饿死 tick/softlockup/抢占;用户 rflags 原样保存,iretq 恢复用户 IF);快路径 SYSRET(rcx/r11 镜像检查),其余 IRETQ;fixup_bad_iret 对齐参考(帧属主死亡,系统存活);#UD 处理器将用户 #UD 经 force_sig_fault(SIGILL) 路由 —— OH processdump/CFI 报告器得以运行。
  • aarch64:SVC 后 ELR 停于下一条指令 —— 系统调用路径永不回退 PC;ERESTARTSYS 重绕为 pc −= 4 落回 svc;系统调用号 x8,参数 x0-x5,返回 x0;pt_regs.syscallno 槽 + orig_x0。
  • 例外表:riscv64 .ex_table 记录 (insn, fixup);uaccess 故障经 handler 查 fixup 跳转,返回未拷贝字节数;x86_64 同形 fixup_exception。uaccess:riscv64 SUM 位(sstatus 18)括号 + 三阶段汇编拷贝(对齐/8 字展开,WORD_COPY_MIN = 71 字节);x86_64 uaccess_safe.rs + AC 括号(D-18:pushfq/orq/popfq 序列替代 STAC/CLAC —— STAC/CLAC 编码在 QEMU TCG 下无条件 #UD,二分实证;括号代价 ~55 ns,硬件与 TCG 双可启动;SMAP-VIOL 信标每启动验证静默);PF-NOCTX 信标:SMAP 开、AC 清、故障址位于用户区且 no_context = 裸用户指针解引用 —— 在 oops 机制污染上下文前点名 rip/addr(cap 8 次;"审计循环 = 跑测试、读该行、改写站点为 uaccess、重复")。

§7设备 MMIO 别名区(D-17,x86_64)

  • 机制:设备 MMIO 一律经内核侧别名窗(两个静态窗 + 动态 ioremap 竞技场,IOREMAP_ARENA 256GB)访问;bootstrap 恒等映射于 boot 栈切换后 UNLINK —— 运行期无任何低恒等窗;固件放置的低 MMIO(RTC 页 0x101000 等)亦映射入竞技场。
  • ioremap_bar_kernel:固定窗先查(不消耗竞技场);重注册检查(两能力共享一 BAR);新块 2MB 对齐、原子前推 DYN_BAR_CURSOR;DYN_BARS 登记表(满则该 BAR 留恒等回退并告警 "user-CR3 MMIO on it will KERNPANIC");USER_MMS_EXIST 守卫在用户 mm 存在后映射时告警(既有用户 CR3 看不到新竞技场链接);调用契约 = 单线程启动上下文(PCI 探测)。
  • 优势:任一 CR3 下统一的 MMIO 纪律 —— 陷阱上下文的设备访问在用户页表下不可故障;uaccess 契约无恒等洞(低用户地址的 copy_from_user 故障而非读物理内存 —— prlimit64 EFAULT 缺口由此闭合)。兼容性:x86_64 套件 1194/1194(含此前红的 EFAULT 行);守卫 = PF-NOCTX 与 SMAP-VIOL 信标静默。

§8Kernel.toml 配置系统

  • build.rs 解析 Kernel.toml(基)与可选 build/.config 覆盖层 —— 整体替换曾为反模式;激活的 cargo feature(platform)优先于 Kernel.toml 默认;产物 config.rs 由构建生成,不手改。
  • 配置承载 [general]/[platform]/[memory] 与架构门控的内核栈策略(D-2 的 kernel_stack_size_x86_64);MAX_CPUS 经 config 进入 trap.S(编译期钳制)。
  • print_status 启动表行:每行装配于单个 80 字节缓冲、单次批量控制台写出(per-byte putchar 曾为每行付整对 UART irqsave 锁 + 16550 逐寄存器流量 × ~150 行)。
