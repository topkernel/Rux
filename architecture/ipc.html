进程间通信

kernel/src/ipc/ + net/unix.rs · binder、PI futex、SysV/POSIX MQ、AF_UNIX —— 机制、锁模型与实测数据 · 语境:OpenHarmony 服务网格(~80 服务集合)在 /data 挂载后全量运行 · 依据:docs/architecture/binder-parity-audit.md、design-divergences.md(D-14)

§1binder(kernel/src/ipc/binder.rs,14,144 行)

binder 是 OpenHarmony 服务网格的核心传输:全部系统服务注册(samgr)、服务调用与 hilog 数据面均经此通道。实现按参考 6.6 binder.c 的语义逐函数对齐,并有专项对齐审计(binder-parity-audit.md)约束后续变更:每处改动必须引用其镜像的参考函数与行号。

  • 协议:版本 8(BINDER_VERSION ioctl 返回);BC_* 全集(TRANSACTION/REPLY、FREE_BUFFER、INCREFS/ACQUIRE/RELEASE/DECREFS 及 DONE 对、REGISTER/ENTER/EXIT_LOOPER、DEAD_BINDER_DONE、TRANSACTION_SG/REPLY_SG);BR_* 全集(ERROR/TRANSACTION/REPLY/DEAD_REPLY/TRANSACTION_COMPLETE/NOOP/SPAWN_LOOPER/FAILED_REPLY 等)。
  • flat_binder_object 跨进程翻译:BINDER_TYPE_{WEAK_}BINDER/_HANDLE 的节点/引用握手(BR_INCREFS → BC_INCREFS_DONE)工作;BINDER_TYPE_FD/FDA/PTR 部分落地 —— FDA fd 生存期为开放项(发送即安装会在未投递事务上遗留幽灵 fd,审计已记录在案)。
  • 同步事务延迟 TRANSACTION_COMPLETE:发送者的读保持睡眠直至 reply 将其携带出 —— 一次唤醒完成整个往返;replier 侧取非延迟形态。
  • mmap 缓冲:静默截断至 4 MiB(与参考 binder_mmap 同行为);重复 mmap EBUSY 先于分配判定;VM_DONTFORK 语义经 sc157→sc159/160 反转 —— OH appspawn 子进程继承守护进程映射,DONTCOPY 已移除。
  • 锁模型:单全局自旋锁守卫全部 binder 对象;锁下不拷贝用户内存、不睡眠 —— BC 载荷在取锁前拷入,BR 载荷在锁内暂存内核 Vec、锁释放后拷出。
  • thread_has_work 对齐:looper_need_return 作为函数的一项合成条件(进程 todo、节点 async_todo、spawned/pending 计数);poll 唤醒扇出与可用性语义一次 diff 收敛四处分歧。
  • 失败回复路由:BR_FAILED_REPLY/BR_DEAD_REPLY 语义 + 静默接收者清扫 sweep_silent_txns(进程 todo + 节点 async_todo,ONEWAY_SILENCE_J 窗)—— 对不履行 BC_FREE_BUFFER 义务的服务守住缓冲回收;TF_UPDATE_TXN(0x40)落地(对齐 binder.c:2734/2832-2845 的 supersede-on-park)。
  • access_token 注册表:/dev/access_token_id + BINDER_GET_SENDER_INFO —— samgr 权限检查依赖;缺失时 AddSystemAbility 拒绝曾导致 OH 显示阻塞(b98–b112 黑屏根因链)。

运行数字与已知代价

  • /data 挂载服务网格 ~89k txns/s 时:binder REST 区段 n=64.4M、累计 592 s(整机 41%)、平均 9.2 µs。
  • 监视行:单事务最长持 IF=0 73 ms —— IPC 门禁的 SLOW-TXN 类(queue ≤ 10 ms 全域;FAIL 判据 queue ≥ 50 ms)监测该形态。

§2PI futex(sync/futex_pi.rs)

  • 操作集:FUTEX_LOCK_PI / UNLOCK_PI / TRYLOCK_PI / LOCK_PI2 + WAIT_REQUEUE_PI / CMP_REQUEUE_PI;cmp-under-lock requeue 与 robust-exit 死亡标记齐全。
  • 实现形态:nice 下界(nice-floor):PiState 存在等待者时,其属主以 nice −20 运行;等待链逐链接行死锁检测,每一链接传递式提升;exit 路径带 owner-died 交接释放 PI 锁。
  • 与参考 rt_mutex 的语义差异(内核侧数值提升 vs nice 折算)登记于实现注释;LTP pi 族 + OH FFRT 负载为守卫。

§3SysV 三件与 POSIX MQ

  • 布局编译期断言:ShmidDsUapi 112 字节(asm-generic/shmbuf.h RV64)、SemidDsUapi 104 字节(rv64)/88(32 位路径)、MqAttr 64 字节(glibc/Linux RV64);IpcPermUapi 字段偏移逐项断言 —— UAPI 结构漂移在编译期不可表达。
  • ipc_namespace 作用域:SysV 对象按调用方命名空间过滤键可见性与 id 解析(1bde7490;LTP msg_comm "消息跨命名空间泄漏"为落地守卫)。
  • POSIX MQ 全功能实现;挂载面 mqueue 为空 tmpfs 别名并携带 MQUEUE_MAGIC 供 systemd 校验(statfs magic 家族修复)。
  • sem 的 MAX_SOPS 上限强制;SIGEV UAPI 值与 notify 校验顺序对齐(3ba353542)。

§4AF_UNIX(net/unix.rs,4,372 行)

  • 类型:SOCK_STREAM / SOCK_DGRAM / SOCK_SEQPACKET(连接态 + 记录边界,短读 MSG_TRUNC)。
  • 抽象命名空间:sun_path[0] == 0 即抽象名 —— 地址即名字,无文件系统节点,/proc/net/unix 以 @name 呈现;autobind "\0%05x" 对齐;UNIX_PATH_MAX=108。
  • SCM_RIGHTS fd 传递 + SCM_CREDENTIALS:cmsg 载荷随 UnixSeg.files/cred 传输,由首个触及该段的 recv 消费。
  • Weak 对端模型:对端链两侧均为 Weak —— fd 是唯一强属主,"对端关闭"即 Weak::upgrade 失败;引用环在该表示下不可构成,成对 socket 泄漏类问题不存在。
  • 单锁发送路径:每 socket 的 recv_queue/accept_queue/state/eof 为独立自旋锁;发送者仅取目标 recv_queue 一把锁 —— 两 socket 间无 AB-BA 可能。
  • 等待纪律:W3 等待队列形态(prepare_to_wait → 复查 → schedule → finish_wait);poll 语义:监听者仅报 POLLIN 不报 POLLHUP;对端关闭且有未读数据 = POLLHUP|POLLIN。
