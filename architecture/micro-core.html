微核架构:类型隔离的内核

kernel/rux-core + 服务 crate 群 · 唯一判据、不可还原底线、三层防线、逐级翻转梯子 —— 全部机制配实测数据 · 设计正本:docs/architecture/micro-core-design.md

§1与 Linux 的根本不同:一条判据分两半

Rux 与 Linux 最本质的区别不在某个子系统的算法,而在信任的计算基础(TCB)如何定义。Linux 是一个 ~2,800 万行 C 代码的单体内核:类型系统不检查内存安全,所以整个内核都是 TCB —— 任何一行代码的任何指针错误都可能破坏任何数据;隔离只能靠代码评审与运行时加固。

Rux 用 Rust 的类型系统把同一件事变成编译期结构。判据只有一条,对每行代码各问一次:

这段代码能否活在 #![forbid(unsafe_code)] 之下?
能 → 它属于服务 crate(编译器保证零 unsafe);不能 → 它属于 rux-core(带 INV 契约或 F 行登记,并被验证栈覆盖)。没有第三种归宿。

推论:服务子系统(系统调用、网络、文件系统叶层、驱动、ext4,以及调度与内存管理的策略层)在其 crate 上加 crate 级 forbid 后,内存不安全在编译期不可表达 —— 野指针、释放后使用、数据竞争这些主导 C 内核 CVE 史的缺陷类别,在服务列结构性为零。这不是"写得小心",是编译器保证:向 forbid crate 添加 unsafe 的唯一途径是删掉 crate 属性本身,而 CI 棘轮把这一删变成显式、可评审的动作。

§2不可还原底线:rux-core ≈3,000 行

每个内核都必须手写一小块底层(参考内核用 arch/*.S 表达)。Rux 的底线逐项登记、每项带参考内核对应物与 F 行编号:

家族估计双计行参考内核对应物
陷阱进入/出口 + 信号帧~500entry.S, sigreturn
上下文切换(三架构)+ tp 寄存器~250__switch_to / cpu_switch_to
uaccess 拷贝底层~320uaccess.S / copy_user_64.S
FPU/RVV/FPSIMD 保存恢复~450fpu/*.S, vector.S, fpsimd.S
页表原子写 + 走查底层~300pgtable.h 原子操作
引导表(GDT/TSS/8259/CSR)~350head.S 等
CR/MSR/CSR/端口 IO 寄存器操作~250special_insns.h, io.h
SBI/虚拟化调用/GIC ABI~150kvm.c, irq-gic-v3.c
同步原语内部 + safety/ 原语 + 任务页生命周期 + 定时器核~420spinlock.c 内部等

这块就是被审计、被机器验证的全部手工 unsafe —— 对照整个 Linux 树皆为 TCB 的口径,比例约为 1 : 9000(3,000 行 vs ~2,800 万行)。

§3三层防线:0 + ~50 + 0 周期

微内核(seL4/L4 族)买故障隔离的方式是每服务独立地址空间,代价是每次跨服务 IPC 约 1,000 周期(最优快路径),沿"缺页→驱动→服务器"链路成倍放大(Mach 的教训)。Rux 用语言隔离替代地址空间隔离,再加一层硬件后备,三层各在自己的成本点工作:

层机制边界成本(实测)买到什么
类型层forbid crate + Cargo 依赖图(Cargo 拒绝环=单向依赖机器检查)0(跨 crate 调用,LTO 内联;翻转验证零行为变化)服务列内存不安全编译期不可表达
硬件层Intel MPK 保护键:同一地址空间内页粒度硬件域47–49 周期/窗口(10 万次 TSC 计时;地址空间切换 ~1,000+ 周期)核心元数据页打标,窗口外访问硬件 #PF(故障注入实证);<1% 预算成立
验证层Kani 12/12 全输入证明 + Miri 零 UB + Verus 窄采用(无界算术引理)0(纯离线)核心 ~3,000 行手工 unsafe 机器检查

一句话:微内核花 ~1,000 周期/边界买第一层;Rux 用 0 + ~50 + 0 买到全部三层,且隔离粒度更细(MPK 到页,IPC 只到进程)。mpkguard 框架已落地(默认关,mpkguard=1 开启):vring AVAIL 段为第一目标(实测 ~2.4k 窗口/秒)。

§4终态拓扑与翻转梯子

rux-core          (≈3,000 行;全部 TCB)
  入口/切换/uaccess/页表 asm · safety/ · 同步原语 · 任务生命周期 · 定时器核
  ← Kani/Miri/Verus 覆盖

rux-sched-policy  forbid safe(CFS/RT/公平性/唤醒策略 —— 决策出核心)
rux-mm-policy     forbid safe(VMA 树/mmap/COW/缺页决策)
rux-syscall       forbid safe(41k 行,12 文件 —— 已完成翻转)
rux-fs-svc · rux-ext4 · rux-net · rux-drivers · rux-ipc · rux-dfx-svc

调度与内存管理不做整个 crate:两者都是"可判定的策略"骑在"小的 unsafe 核"上,劈分后策略层 forbid、核留 core —— 切换/tp/锁原语/页表原子写是 TCB,CFS 数学不是。每级翻转的绑定次序:测量反向依赖面 → 缝设计 → 翻转 → forbid → 域电池(调度劈分过 P4 风暴+上下文切换基准;内存劈分过 mmap/缺页族);测量显示不可分解的级搁置并留数字 —— 搁置是成功,不是失败。
