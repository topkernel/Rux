锁序与并发不变量

触碰任何锁嵌套前必读 · 权威源:docs/architecture/lock-ordering.md(INV-LOCK-*)

§1全局锁序表

Level 0  IRQ(关中断状态)
Level 1  preempt(抢占计数)
Level 2a GRQ(全局运行队列)
           ├─ Level 3a  zone(buddy)
           └─ Level 3b  futex 桶 → Level 4  等待槽
Level 2b 进程树          Level 2c  inode          Level 2d  dcache
  • 同层各支(2a/2b/2c/2d)互不嵌套;纵向只能从低编号向高编号获取。
  • SleepMutex 在层外:VFS_MUTATION_LOCK → EXT4_BIG_LOCK 是唯一合法休眠锁序(INV-LOCK-8)。
  • virtio:动任何 virtio 路径前先读本页与源内注释 —— net 的 {rx|tx}_queue → stats 单向序(INV-LOCK-6)曾被 AB-BA 互旋定罪。

§2具名不变量(INV-LOCK-*)

编号内容
INV-LOCK-5/6驱动队列锁 → 统计锁单向;看门狗守护(曾有 poll 持 stats 跨 refill 的双 CPU 互旋)
INV-LOCK-7per-mm PTE 锁:全局 epoch(RwSpinlock 读)+ 每 mm 自旋 split 模式;锁序位置在 vma_manager 之后、page_desc 之前;三架构统一
INV-LOCK-8休眠锁唯一序:VFS_MUTATION_LOCK → EXT4_BIG_LOCK
INV-LOCK-PI-1PI futex 新类:plain 桶 → PI 桶 → PI 池槽

§3类型化锁键(分歧 D-11):嵌套是编译事实

  • 零尺寸键类型(GrqKey / FutexBucketKey / NetQueueKey / WaiterSlotKey…);嵌套关系 = CanNestInside trait impl 表。
  • 外层 guard 铸造 NestProof,内层 lock_nested(&proof) 消费它 —— 反向获取不编译,零运行时开销。
  • 警示案例:GRQ 首版协议包装曾因 lock() 返回的 guard 被裸语句丢弃,所有临界区未互斥 —— 13-boot 配对测量撤回;此后两类 keyed guard 标注 #[must_use],协议方改用 lock_claim()。
  • 已采纳:GRQ 本体、futex HASH_HEADS 桶、WAITER_POOL 槽(futex_wake 唤醒链每跳索 proof)。

§4运行时守护网

  • SPIN 模型检查(4 个):futex_wait_wake / lock_ordering / interrupt_preempt / sched_enqueue_dequeue —— make spin。
  • S-1 loom/Kani 镜像:SleepMutex 状态机证 INV-M1..M5;启用头 90 秒抓到真实 pid-0 递归 bug。
  • 自旋锁看门狗(dfx=watchdog,遗留):死锁告警自动全任务快照;带 key 名输出。
  • census + heal:每任务逐字段 tick 观测,幻影 preempt-count 200 tick 判定;model-vs-reality MISS=0(64.5k/52.1k heals 实测)。
  • allocwatch:跨 CPU 持锁者命名(等待者不能自报 —— 打印会分配,而它正停在分配器里)。

§5锁语义政策

锁/同步原语的语义完全参照参考内核,不自创。"不可睡眠调用者持锁"一类问题在调用点重构(trylock/推迟),不给锁加路径。公平性设计争议(如"自旋 2 秒再强抢")已被裁决否决,相关实验分支永不合并。
