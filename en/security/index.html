Security overview

The security argument's hub: the thesis, the four sub-pages' map and the headline numbers — every claim carries its mechanism, data and source on a sub-page · Living document: docs/architecture/safety-and-performance.md (evidence collected every merge round)

§1The thesis

Security checks happen at compile time and disappear from the fast path — the fast design and the safe design are the same design.Traditional kernels trade safety for speed on the hot path; this kernel moves the checks into the type system and build time, so the fast path no longer pays for them. §5 below gives the per-item "performance result ← the security property it carries" pairing.

§3The composite argument: why these numbers amount to "safe enough"

  1. Class elimination (compile time): the expression-level defect classes dominating C-kernel CVE history (overruns/iterator invalidation/wild pointer arithmetic/format strings) are unrepresentable in safe code — the taxonomy's 0 is that claim's empirical face; the unsafe surface is 10.6% and audited block by block.
  2. The residual class has dedicated countermeasures: the 10 safe-class defects are all ownership/refcount/lock-protocol/stack-depth decisions — precisely the targets of model checking and symbolic execution: loom's interleaving enumeration (caught a real lock-protocol defect in its first 90 seconds), Kani proving invariant tables for all inputs, proptests pinning scoring/encoding/algebra rules.
  3. Proof validity is process-guaranteed: the mirror-sync discipline makes kernel-vs-mirror drift fail the build directly — a proof cannot silently stop covering its code; the CI layering (light per-push + heavy nightly) ensures the instruments actually run.
  4. The defect surface is designed: panic paths contained instance by instance (a dozen-plus regression receipts); instrument misjudgments and negative results archived with receipts — the adjudication discipline is itself audited.
  5. Runtime defenses + honest gaps: SMAP/SUM/exception tables/seccomp/capabilities/stack guards present with measured costs; the gaps (KASLR, text W^X, stack protection etc.) each state their closure shape rather than being avoided.
