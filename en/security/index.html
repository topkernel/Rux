Security & formal verification

Bug taxonomy · unsafe-surface ledger · formal verification · runtime hardening · honest gap register — living document docs/architecture/safety-and-performance.md, evidence accrued every merge round

§1Thesis

Security checks happen at compile time and vanish from the fast paths — the fast design and the safe design are the same design. C kernels trade safety for speed; Rux moves the important checks into the type system and build time so the fast paths no longer carry them. §8 pairs each performance number with the safety property it carries.

§3The unsafe surface and layered governance

  • Enumerated and contracted: unsafe lines are 12.9% of the kernel; the Framework layer carries 1,340 unsafe tokens (each block requiring a // SAFETY: comment; coverage 3,207/5,009 = 64%).
  • Service layer targets 100% forbid: 47 files compile-time forbid(unsafe_code), 56 more already unsafe-free; the first named shrink target syscall/io.rs went 69 tokens → 0 (typed entries + uaccess_safe typed copy_in/copy_out).
  • Layering (kernel-layers.md, longest-prefix match, unmatched files default to the safest bucket): Framework (arch/mm primitives/interrupt/virtio core/trace/perf) allows audited unsafe; the service layer forbids it; dfx/ diagnostics are tracked separately; the trace module bans unsafe entirely.
  • Capsule boundary: syscall entries validate and translate user pointers in one place; nothing else in the kernel touches user memory directly.

  • Mirror-sync discipline: the verify crate hand-mirrors the proved algorithms and scripts/verify_sync_check.py enforces byte-equivalence with the kernel originals — proofs stay pinned to the code they cover; a kernel change without its mirror update fails make verify and the CI gate.
  • Cadence: per-push (mirror sync + full proptest) → nightly (Kani all harnesses / Miri / SPIN — they do not fit a per-commit budget) → manual (make verify && make kani before declaring a proof-bearing change done).
  • Catch record: the concurrency-primitive state-machine mirror (SleepMutex; loom 8 interleavings + Kani proofs of INV-M1..M5) caught a real pid-0 recursion bug within its first 90 seconds (011a71c5); exhaustion also yields a design-characterization proof — with pure fair contention two tasks cannot strand, and 3+ waiters need the R85 timer bound.

§5Runtime hardening inventory (present)

  • User/kernel boundary: SMAP (enabled via the EFLAGS.AC bracket, D-18, ~55 ns — avoiding the TCG STAC/CLAC #UD), CR0.WP from the earliest boot, no identity MMIO window (D-17 — uaccess has no identity hole), PF-NOCTX/SMAP-VIOL beacons silent across the whole suite.
  • Userspace: W^X (NX mappings, PT_GNU_STACK, READ_IMPLIES_EXEC), seccomp (STRICT/FILTER + NO_NEW_PRIVS), capabilities (41 CAP_* UAPI numbers).
  • Kernel-stack guards: stack canaries, depth probes (KSTACK-HW), a 0xC3 scribble ring on free.
  • Deferred-free isolation: MmStruct/Task enter a 16,384-slot timer ring drained at 1500 ms — reclamation strictly separated from use.
  • Failure discipline: Oops/panic in the reference report shape (CSRs + all GPRs + 32-frame backtrace), panic_on_oops sysctl, panic= reboot, pstore console.
  • Observable safety net: unified tracepoints (51 events / 16 groups), census + heal self-correction, watchdog, kallsyms-symbolized backtraces.

§6The panic surface is a design surface, not a latent one

  • Every panic instance that ever fired was eliminated with a regression test (a dozen receipts on file): the UTF-8 printer family (non-UTF-8 comm once broke the panic printer at t=209 s), negative-memo null deref, mmprof slot namespace, the debug switch table, memwatch PFN bounds, binder dead-proc expect → bounded warning, timer same-CPU IRQ reentry, ext4 empty index root, aarch64 regs[31].
  • Principle: loud and caught beats silent corruption — bounds checks turn OOB writes into panics instead of letting corruption proceed.
