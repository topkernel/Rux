rt-tests (cyclictest / hackbench / pi_stress)

Real-time latency and scheduling stress, compared on the same image, binaries and rig; a row without numbers is a failure · rig and method

§1Data (same image, same binary, same rig)

Both sides run the same image, the same rt-tests v2.11 static binaries, the same parameters — Rux (main release) vs the reference kernel (same-image guest kernel 7.0.0-38). cyclictest: a 30 s window, a 1000 µs interval, mlockall; hackbench: message-passing throughput (seconds, lower is better). The cyclictest rows currently carry Rux release single-boot measurements beside reference full-suite columns (different boots); the same-rig interleaved re-measurement is in flight.

A row without numbers is a failure: hackbench inet ≥2 groups has no number on Rux (loopback non-blocking-connect stalls; on record with the net lane); pi_stress once failed initialization on Rux (the PI-mutex UAPI chain) — this table carries the newest two-sided readings, and failed items show as such in their rows.

§2Rig and method

  • The pair: the same kernel pair, image (reflink) and injected binaries as the fio page (source tarball committed; musl-static builds with a numa shim and the musl sched_* ENOSYS-stub override).
  • Protocol: one boot per side runs all items in sequence (the qsrun cmds protocol); cyclictest prints its statistics lines and hackbench its elapsed times directly.

§3Toolchain

  • The rt-tests v2.11 upstream source is committed; built by userspace/tests/rttests/build-x86.sh; schedprobe (injected every boot) verifies the raw sched_* syscall surface.
  • Extension: test/qrtests/run-suite-x86.sh "60 cyclictest -D 30 -i 1000 -m"; the histogram mode (-h to file) and a reference-kernel column are in the queue.
Canonical: the qa-suites worktree run/qa-suites-findings.md; raw serials run/bench-pair-1117/ (both arms).
