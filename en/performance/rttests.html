rt-tests (cyclictest / hackbench / pi_stress)

Real-time latency and scheduling stress, compared on the same image, binaries and rig; a row without numbers is a failure · rig and method

§1Data (same image, same binary, same rig)

Both sides run the same image, the same rt-tests v2.11 static binaries, the same parameters — Rux (main release) vs Linux (same-image guest kernel 7.0.0-38), same-rig interleaved (3 runs per form). cyclictest: a 30 s window, a 1000 µs interval, mlockall; hackbench: message-passing throughput (seconds, lower is better). The cyclictest rows carry clean-pass values; loaded-pass maxima are host-load waves both sides share, labeled as such in the rows.

§2Rig and method

  • The pair: the same kernel pair, image (reflink) and injected binaries as the fio page (source tarball committed; musl-static builds with a numa shim and the musl sched_* ENOSYS-stub override).
  • Protocol: one boot per side runs all items in sequence (the qsrun cmds protocol); cyclictest prints its statistics lines and hackbench its elapsed times directly.

§3Toolchain

  • The rt-tests v2.11 upstream source is committed; built by userspace/tests/rttests/build-x86.sh; schedprobe (injected every boot) verifies the raw sched_* syscall surface.
  • Extension: test/qrtests/run-suite-x86.sh "60 cyclictest -D 30 -i 1000 -m"; the histogram mode (-h to file) and a Linux column are in the queue.
Canonical: the qa-suites worktree run/qa-suites-findings.md; raw serials run/bench-pair-1117/ (both sides).
