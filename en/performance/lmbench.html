lmbench 3.0-a9

Latest state: the authoritative same-rig KVM table (12 latency + 8 bandwidth rows, each row the newest measured value on current main) · Canonical: docs/test/lmbench-report.md

§1lmbench data (same-rig KVM, 21 cases)

Source: the "Standing (2026-11-16, kernel main=017bf556b)" section of lmbench-report.md — the single authoritative table; the data below is that section. Method: both sides in the same rig (q35/KVM/-cpu host/smp2/2G, host CCD0 pin + performance governor + warmer thread); Rux boots with nohz_full=1, one case per boot with the retry rule; the Linux column runs the OHOS 6.6.101 kernel in the same guest rig with the same static binaries, 2 reps, medians. The switch/wakeup family is reference-window-sensitive — ratios are only meaningful within one session.

Basis: each row carries the latest measured value on current main (the 2026-11-16 full battery; the null/read/write rows re-measured 11-17). The Rux column follows each round's own build class; the Linux column = the host 7.0.0 kernel booted in the same guest rig running the same static binaries.

Mechanism note: the wins concentrate in scheduler/wakeup and IPC (cross-vCPU wakeup IPIs are expensive under virtualization; the single global run queue produces no cross-core reschedule storm) and memory bandwidth; syscall-latency rows run the guest's own entry (no vmexit), so the gaps there are real kernel differences. Rows without honest numbers this round: lat_mmap/lat_pagefault/bw_mmap_rd (not printed by this battery) and the net-server family (lat_tcp/udp/connect, bw_tcp, lat_fs) — not listed. The historic r14 table (2026-11-08 window) is archived in lmbench-report.md.

Correctness bugs the campaign found and fixed (the performance gaps were hiding them): a stale-rsp0-at-free UAF (the fork bistability root cause); a call_rcu zero-grace callback firing; a wake-monitor staleness inversion; the fdreap per-tick 10 ms close stall; the mainline munmap final-TLB-flush loss (5b4a4bc7).

§3Reproducing

# the full battery (one boot per case + the retry rule)
cd userspace/lmbench && ./extract-lmbench.sh && ./build-lmbench.sh && ./build-rootfs.sh work/lmbench-x86.img && ./run-rux.sh
# the quick path (10 headline cases, ~3 minutes, marked INDICATIVE)
./quick.sh [bzImage]
