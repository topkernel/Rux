§2Test platform and capture method

  • Test platform: the 9950X host, q35 KVM -cpu host -smp 4 -m 4G, the strong build (build-release-opt); one boot per full run, 2700 s outer / 900 s in-guest budget.
  • Score capture: a local TLS capture server (a self-signed CA injected into the guest /etc/hosts via debugfs, pinning browser.geekbench.com to 10.0.2.2; a :443 server receives the HTTPS upload POST, parsed by parse-capture.py) — scores never touch the external network and the process is replayable.
  • Kernel bugs this suite found and fixed: mprotect returning ENOMEM for mid-VMA resizes; the TCP RX checksum reading stack garbage — commercial suites as compatibility probes.
  • An accounting note: the per-workload tables above are the 11-04 full capture (that round's SC 2115); the single-core AES-XTS takes the post-fix re-measurement (8047/8140), the historical low being the serial-print-tax artifact (AES-NI probe-verified intact). The 11-15/11-16 totals are the four-boot best; a per-workload re-capture is in the queue.
