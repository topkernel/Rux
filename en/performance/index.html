§1Verdict: where we lead and lag vs Linux

Every comparison against Linux on this page is same-host, same-accelerator: the same host (9950X), the same QEMU q35 + KVM (-accel kvm -cpu host), the same image shape, the same static benchmark binaries. No native columns.

📏lmbench same-rig: 9 of 14 paired cases ahead, 5 behind

Ahead: page fault 2.26–2.45×, lat_mmap 4.2×, pipe 3.56×, context switch 3.39×, lat_unix 3.14×, lat_sem 2.62×, bw_pipe 2.68×, bw_unix 1.88×, read 1.02×.

Behind (Rux/Linux): open 1.82×, stat 1.32×, null 1.17×, fork 1.11×, write 1.10×.

best lead 4.2× · worst lag 1.82× · data in §2

🏁Geekbench 5: multi-core +4.3%, single-core +5.1%

Multi-core total 7332 vs 7027 (+4.3%): 8 workloads ahead / 5 parity / 8 behind. Single-core total quiet best 2274 vs 2165 (+5.1%): 13 ahead / 3 parity / 5 behind.

per-workload data in §3 · rig note: Linux side is the host 4-CPU pin (taskset, topology-matched)
Gap structure: the wins concentrate in the scheduler/wakeup paths (context switch, pipe) — Linux's cross-vCPU wakeup IPIs are expensive under virtualization while Rux's single global run queue produces no cross-core reschedule storms — and now also in page fault / mapping (seven campaign rounds turned the page fault from the worst deficit into a 2.26–2.45× lead). The remaining deficits are syscall entry and path resolution (open 1.82×, stat 1.32×) and fork (1.11×) — write is 6 ns from parity and read is already ahead. Data: the perf-gap-hunt seven-round campaign (interleaved same-window A/B per row, med-of-3+3).

§5Method and rig

  • Same host, same accelerator: both sides on the same host, the same QEMU q35 + KVM (-accel kvm -cpu host), the same Ubuntu rootfs shape, the same static benchmark binaries; one case per boot (the serial console interleaves with long sweeps, so a single-case boot is the only clean collection), PID 1 runner, 35 s in-guest budget (exceptions noted per case).
  • Comparable-class rule: debug vs release-strong never cross-compared (strong reads 10–30× lower on the floor families); TCG vs KVM never cross-compared.
  • Anchor provenance: gate anchors read only Rux's own medians — the Linux column never enters a Rux gate anchor (leg 32 found four cells transcribed from the Linux column; corrected and filed).

§6The merge-gate performance dimension (three tiers + six domains)

Every merge is reviewed for both function and performance; baselines move only through merges that passed their own tier; a regression blocks the merge until fixed or justified in writing. Workflow details: Contributing §3.

§10Optimization queue (open gaps, priority order)

  • Syscall entry and fill/copy tail: null 1.17× / open 1.82× / stat 1.32× / write 1.10× (same-rig) — entry-floor and fill/copy tail (SMAP AC brackets); fd lookup is no longer the bottleneck (fstat already ahead).
  • lat_proc fork 1.11×: retire batch-park in flight.
  • AES-XTS single-core: root-caused and fixed (print-tax artifact, re-run 105–106%); residual single-core rows (Text Compression 94% / Navigation 81% / PDF 85% / Clang 88% / Face 87%) await isolated re-runs.
  • Network family: bw_tcp TIMEOUT / lat_connect 14–16 ms — a scheduler stale-claim refuses the accept server/worker wakes (WAKE-HEAL-SKIP ×39); connect and data paths themselves work, and TCP throughput can only be measured after the fix.
  • Backfill queue: a fio throughput benchmark (same-rig Linux baseline, direct=1 to bypass the page cache); same-rig KVM Linux comparisons for the remaining lmbench cases (lat_mmap family is already paired) and for Geekbench; page-cache hit-rate absolutes, PCP watermarks, binder throughput.

§11debug measurement toolchain

  • syscost: boot census (syscall volume, census counts, tick rate, per-op averages) — the Tier 1 collector.
  • pbench (test/pbench.c): the P1–P7 microbenchmark probes — the Tier 2 collector.
  • census / wakewatch: scheduler-stall census (WAKE-STRANDED) and wake→run latency forensics (1024-slot side tables + pick-skip reason table).
  • if0 v3: EFLAGS-pair probe — the official IF=0 share and cli-segment measurement (on main; no more tick-mode proxy).
  • fsw / mmprof counters: fs sync-write classes, memory accounting reconciliation (OOM forensics).
  • run/perf-gate.sh: gate automation (anchor JSON + tier dispatch + band verdicts).
  • Unified tracepoint framework: 51 events / 16 groups, byte-exact tracefs, +13–19 ns per record when enabled (see Observability).
