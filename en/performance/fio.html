fio 3.36

Storage-I/O performance comparison (same image, same binary, same rig): throughput and latency; an engine row without numbers is unavailable · rig and method

§1Data (same image, same binary, same rig)

Both sides run the same ext4 image, the same static fio 3.36 binary, the same job file — Rux (main release) and Linux (same-image guest kernel 7.0.0-38) in the same rig (q35/KVM/-cpu host/SMP8/8G, virtio-blk; interleaved boots ×3, medians); direct=1 bypasses the page cache. Each row carries its newest measured value; same-window kernel-vs-kernel ratios drift with host-load windows on BOTH sides (±10% class) — ratios are meaningful only within one window. An engine row without numbers is currently unavailable.

§2Optimization method

Gaps are attributed by a two-sided same-rig accounting (both kernels on the same image and workload, per-op cost decomposed segment by segment via a shared tracefs event timeline + phase cycle brackets + perf on both sides: syscall entry / block resolution / submit+kick / device / completion IRQ / wake / return), then each is rebuilt along Linux's implementation shape: the direct path submits physically consecutive runs in one request; MSI-X with completions walked inside the hardirq vector; synchronous waits poll briefly before sleeping (the completion object is a plain kernel value — at depth 1 the whole sleep machinery costs more than the device round trip; Linux makes the same trade, only opt-in); bulk unwritten-extent conversion with neighbor merge (one tree edit per write span); per-inode dirty-block notes → an O(dirty) fsync walk (the tagged-page-tree analog) with the inode-table block riding the same flush window; buffered writes copy user pages straight into page-cache frames (the copy_page_from_iter shape); directory reads fill incrementally; path and descriptor costs (conditional-refcount close = the fget_rcu shape, readahead state embedded in File); empty leaf tables freed on address-space teardown. Every change is A/B'd on the same rig, image and binary; negative results stay on record (MSI destination steering is a dead end under this QEMU/KVM+irqfd). Method and per-item evidence: docs/test/perf-campaign-2026-11-17.md.

§3Rig and method

  • The pair: Rux (main release) vs Linux (same-image guest kernel 7.0.0-38), the same QEMU q35 + KVM (-cpu host SMP8/8G), the same ext4 image (reflink copy, booted snapshot=on), the same static binary (source tarball committed; built by userspace/fio/build-x86.sh); interleaved boots ×3, medians.
  • Protocol: one boot per side runs all jobs in sequence (the qsrun cmds protocol); fio terse single-line output goes into the serial capture with the bw/IOPS/latency fields.
  • Basis: direct=1 rows are the real device path; the buffered-write row is the page-cache-absorbed basis (both sides); ratios are meaningful only within one session.
