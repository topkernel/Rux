Scope note: this round used fio to verify IO engine paths and data integrity, not throughput (no same-rig Linux baseline exists; the multi-group ~700 MiB/s reading is an incidental page-cache-absorbed number). IO throughput performance is carried by §8 pbench P6 (Rux anchors: write_fsync 8442.6 / mkdrmdir 216.7 / unlink 54.6 / append 5.19 µs) and §2 lmbench bandwidth rows (bw_pipe 2.68×, bw_unix 1.88× vs Linux); a fio throughput benchmark is on the backfill queue. Post-completion note: the numjobs process-group reaping phase showed F-8 (the F-5 family: parked forker + KOT-KILL cascade, a scheduler-handoff issue handed to the sched lane); fio's own results are unaffected (rc=0, data correct). netperf / iperf3 / sockperf network benchmarks are on the qa-suites charter but have not run yet.

§3Registered gaps and adjudications

  • F-6 (posixaio): a 1-in-6 chance of a boot wedge — fdreap retire_complete's RCU grace never passes (the monopolist-window family); 4 directed reproductions + 2 replays failed to capture it again (1/6 stands); the signature is the unreapable fio child at T=150s + a hung-task pid >120 s + the fdreap close-completion stall flood.
  • libaio: io_setup/io_submit all ENOSYS (a UAPI gap, syscall/memory.rs); fio exits cleanly with err=38 — correct errno discipline: unimplemented, not misimplemented.
  • F-7 (io_uring): setup returns an fd and the ring mmap is served by io_uring_mmap_handler, then the enter contract dereferences NULL+0x1e → user SIGSEGV (2× SIGDEATH + a teardown #GP); the kernel stays alive — incomplete ring semantics, registered as an io_uring deepening item.
  • F-8: the numjobs boots observed a parked forker + KOT-KILL cascade at teardown (the qsrun forker pid 306, 128 KSIG9s) — fio's own results unaffected (rc=0, data correct); handed to the scheduling lane.

§4Rig and extension

  • Rig: x86_64 KVM q35 -cpu max smp2/2G, virtio-blk (a private ext4 copy at run/rootfs-qa.img), dfx=taskdump,watchdog; one boot per workload class, 20 boots; PID 1 = /test/qa/qsrun (the cmds protocol: budget + program lines, QSRUN-BEGIN / RES|name|rc|tail / QS-ALL-DONE).
  • The fio build: static musl 3.36 (the libaio engine built in), the source tarball committed, built by userspace/fio/build-x86.sh.
  • Extension: append .cmds files under userspace/ci/classes/ (the line format <budget-s> fio --name=… --filename=/test/qa/<file>); run with INJBINS=run/fio-bin test/qrtests/run-suite-x86.sh -f "run/<class>.cmds".

§5The 2026-11-17 re-run (current main debug kernel)

  • Workload classes re-run: 48M direct write / 48M direct read (20 s) / 48M direct randrw (15 s) / 64M buffered write — 4/4 rc=0; the earlier 512M direct-write ENOSPC was the image's free-space constraint (~70M available), not a kernel defect; the job-size boundary is on record.
  • Latency-percentile capture did not land: the JSON was written via the dump tool and captured by qsrun, but the RES tail truncation kept only the distribution tail — the percentile data is unreliable and not published; full-JSON retrieval (debugfs extraction outside the image or a larger tail budget) is in the queue.
  • Same-host noise declared: other lanes' QEMUs ran on the same host during the re-run window; group-level throughput readings are influenced by it — this re-run records pass/fail and boundaries only, and the throughput conclusions remain with rounds 5/5b.
