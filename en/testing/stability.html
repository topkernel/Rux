§2Runtime and desktop session gates

  • The full GNOME session 2,100-second gate (M1–M5 milestones, zero panic) reproduced across three independent boots (2026-10-27).
  • The desktop session held 45 minutes with zero panics (the end-to-end GDM chain, 2026-11-01); boot-to-login ~4.5 s (4 vCPU MTTCG).
  • The GUI verifier (test/ubuntu-gui/verify.py): 23 pixel/serial checks per boot; typed terminal conversations pixel-identical across two independent boots (convcheck).
  • OH side: bootanimation → SystemUI lock screen → the 135+ service set, continuously walked by the fleet's monkey members (see Stress).

§3Self-correction (census + heal)

  • Per-task per-field tick observation + phantom preempt-count adjudication (200 consecutive ticks; legitimate brackets are microsecond-scale) + a 20 ms starvation bound + a softirq dispatch-latency gate.
  • Measured: 64.5k/52.1k heals totaling 605 ms, model-vs-reality MISS=0; IF=0 share 25.7% → 20.4%; longest closed cli segment 594–599 ms one-shot → 6–9 ms; WAKE-STRANDED 233 → 31.
  • Every qualified quiet boot reads the same census exactly (TERM-DESCHED 8, WAKE-REFUSED 32) — stability itself is a gated standing metric.

§4Adjudication discipline

  • Flake isolation: new failures isolated-rerun 2× before adjudication (host-load timeout/precision families: accept02, getrusage04, kill02, genfmod, rename/statfs); the perf gate follows the same rule (rerun once before calling a regression).
  • NOT-OURS ledger: the same binaries run on the host Linux kernel; identical failures are test/environment issues.
  • Instrument misdiagnoses archived: PTGUARD/FREEGUARD false positives (mapcount=−1 is the PAGE_MAPCOUNT_BIAS sentinel), the first PT_LEDGER false double-free + a real frame leak, a GRQ race theory that was wrong — negative results with receipts stay in the record.
  • The panic surface is designed: every fired panic instance retired with a regression test (the UTF-8 printer family, negative-memo null deref, mmprof slot namespace, and more) — see the Security section §6.
