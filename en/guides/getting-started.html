Getting started

From a bare environment to a booting kernel in ~15 minutes — mirrors docs/guides/getting-started.md

§1Requirements

Rux develops and runs on an ordinary Linux host — no special hardware.

ClassDependencyPurpose
Requiredrustup / rustc (stable or nightly)the kernel itself is pure Rust (no_std)
RequiredQEMU ≥ 5.0system emulation (qemu-system-riscv64 / x86_64 / aarch64)
Requiredriscv64-linux-gnu-gcccross-compiling userspace programs
Optionalwhiptailthe make menuconfig TUI
Optionalgdb (riscv64-unknown-elf-gdb)make debug kernel debugging
Optionale2fsprogsmkfs.ext4 -d for rootfs images
 
# Ubuntu / Debian
sudo apt-get install gcc-riscv64-linux-gnu binutils-riscv64-linux-gnu \
     qemu-system-riscv e2fsprogs

# Arch Linux
sudo pacman -S riscv64-linux-gnu-gcc

§2Code and toolchains

git clone https://github.com/topkernel/Rux
cd Rux

# add the Rust cross targets
rustup target add riscv64gc-unknown-none-elf
rustup target add riscv64gc-unknown-linux-musl

The toolchain/ directory carries a self-built musl cross toolchain (Ubuntu ships no gcc-riscv64-linux-musl package): make sdk builds toolchain/riscv64-rux-linux-musl/ (headers + libc.a + a musl-gcc wrapper), the prerequisite for userspace builds. The x86_64 musl sysroot ships as a tarball that make user restores on demand.

§3Building

The kernel

ArchitectureCommandRust targetQEMU machine
riscv64 (default)make buildriscv64gc-unknown-none-elfvirt
x86_64PLATFORM=x86_64 make build or make build-x86x86_64-unknown-noneq35
aarch64PLATFORM=aarch64 make buildaarch64-unknown-nonevirt (gic-version=3)

Other modes: make -C build build-release (optimized), make bin, make clean. Configuration lives in Kernel.toml, compiled by build.rs into kernel/src/config.rs — see Kernel configuration.

The full userspace stack

make build     # ① the kernel
make sdk       # ② the musl libc SDK (prerequisite for userspace)
make user      # ③ userspace programs (Rust std + musl; runs sdk + probes first)
make toybox    # ④ toybox, 200+ command-line tools
make mrsh      # ⑤ a POSIX shell
make rootfs    # ⑥ pack the minimal rootfs image
Guest-side test-case sources are archived as userspace/probes/probes.tar.gz; make user / make test restore them into test/ via scripts/extract-probes.sh — no manual steps.

§4Running

The minimal system (an mrsh shell)

make run

Builds if needed, then enters the serial console at /bin/sh. Try ls /, toybox cat /proc/cpuinfo, echo "Hello Rux!".

Ubuntu 22.04 GNOME desktop (x86_64 + KVM)

make ubuntu-run

Builds (or reuses) the Ubuntu GNOME disk image and boots it in an SDL window; log in as root / rux. Overridable variables:

SMP=1 make ubuntu-run      # single core (default SMP=4)
ACCEL=tcg make ubuntu-run  # disable KVM (KVM by default)
THREAD=single make ubuntu-run # single-threaded TCG for deterministic debugging
Note: the GUI entry point is make ubuntu-run. Shared images boot only with -snapshot + file.locking=off — the image itself is never written.

OpenHarmony

OH boots through the dedicated driver script scripts/test/debug/oh-boot.sh (q35 + virtio-gpu, 7 OH images, serial to file, the QEMU monitor on a unix socket for screenshots). The porting plan: docs/development/openharmony-port-plan.md.

§6Running the tests

The in-kernel suite

make test                          # riscv64 (default)
PLATFORM=x86_64 make test          # x86_64
PLATFORM=aarch64 make test         # aarch64

All assertions run inside the QEMU guest. Current baseline: riscv64 1267/1267, x86_64 1263/1263 (2026-11-01, 73 test files) across memory / process / fs / ipc / signal / network / driver / syscall.

LTP

make ltp            # build LTP on the host (needs sdk; 1,838 official binaries)
# inside the Rux shell:
cd /test/linux-ltp
./run_quick.sh

Formal verification (four layers)

The GUI has a CI-style verifier: python3 test/ubuntu-gui/verify.py --runs 2 --smp 4 (23 checks per boot).

§7Kernel configuration

make config        # view (cat Kernel.toml)
make menuconfig    # TUI configuration (12 categories)

Common Kernel.toml sections: [memory] (kernel_heap_size / physical_memory / page_size), [smp] (max_cpus), [network] (eth_mtu), [printk] (log_level), [performance] (opt_level / lto). Changes trigger a rebuild; the generated kernel/src/config.rs is never hand-edited. The repository's current Kernel.toml is authoritative (a few defaults move with lane needs, e.g. kernel heap size).

§8Troubleshooting

SymptomFix
error: target not foundre-run the two rustup target add commands
riscv64-linux-gnu-gcc: command not foundinstall the cross toolchain (apt / pacman, §1)
qemu: unsupported machine / could not load bootloaderupgrade to QEMU ≥ 5.0 (ships OpenSBI) or point -bios manually
fs: ext4 mount failedin order: make sdk && make user && make toybox && make rootfs
test timeoutskill leftover QEMU processes and retry; or use a release build
Load/Store access faultmake clean && make build, confirm the kernel version matches
configuration not taking effectcargo clean, rebuild, check cat kernel/src/config.rs
