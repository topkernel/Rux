Debugging

Logging · panic forensics · the trace system · debug switches · deadlock detection · performance debugging · memory forensics · GDB — consolidating docs/guides/debugging.md, kernel/src/debug/ and kernel/src/trace/

§1Kernel logging

  • The serial console is the primary log (console=ttyS0): everything prints to UART during boot; once the scheduler is up the default level drops to emerg, and userspace reopens full console output with dmesg -n 7.
  • Log levels 0–7 match the reference kernel (emerg…debug); macros: pr_emerg! / pr_err! / pr_warn! / pr_info! / pr_debug! (println! is an alias of pr_info!).
  • A 1 MB kmsg ring buffer takes every message; read via /proc/kmsg, syslog(2) (actions 2/3), dmesg.
  • Persistent log (off by default): uncomment one line in kernel/src/main.rs and panic logs survive reboots in /var/log/kmsg; extract offline afterwards with debugfs (§7).

§2Panic forensics

The panic handler bypasses the log level and writes straight to UART, then halts with wfi. A full report carries:

  • The PANIC message + file:line (the panic! arguments and source location)
  • The four CSRs: sstatus / scause / stval / sepc
  • All 31 GPRs (saved by inline assembly before any unwinding)
  • A backtrace: up to 32 frames of the frame-pointer chain (s0/fp) as Call trace:

How to read it

FieldReading
scausebit 63 set = interrupt; exception codes: 0 misaligned fetch, 2 illegal instruction, 8 U-mode ecall, 12 instruction page fault, 13 load page fault, 15 store/AMO page fault; interrupt codes: 5 timer, 9 external
sepcthe address of the trapping instruction
stvalpage fault = the faulting virtual address; illegal instruction = the instruction bits
Call tracethe first address is the panicking function's return address (ra); the rest are caller return addresses up the stack

Symbolization

riscv64-linux-gnu-addr2line -e <kernel.elf> -f -C <addr>   # per address
# x86_64: x86_64-linux-gnu-addr2line; feed a whole trace's addresses in one command

The compile-time symbol table (D-3) also provides /proc/kallsyms (22.6k symbols) and native Oops/backtrace symbolization; kallsyms-smoke.sh pins the coverage.

§3The trace system (unified tracepoints + tracefs)

All new observability goes here (the observability policy, 2026-11-02). The single-declaration table (D-15) defines each event's whole face in one row: group/name/id/verbatim print fmt/field list/typed record function/renderer. Currently 61 events / 20 groups: sched (9), ext4 (7), lock (6), rux (5), net (5), binder (5), kmem (4), tcp (3), raw_syscalls / jbd2 / irq / exceptions / block (2 each), vmscan / timer / sock / signal / printk / oom (1 each).

The file tree (/sys/kernel/tracing, reference-aligned)

mount -t tracefs none /sys/kernel/tracing
cd /sys/kernel/tracing
ls
# tracing_on  trace  trace_pipe  available_events  available_tracers
# current_tracer  set_event  buffer_size_kb  snapshot  options/  events/…
ls events/sched/                       # one directory per group
cat events/sched/sched_wakeup/format   # field list + print fmt (byte-identical to the reference)

Typical usage

echo 1 > tracing_on                                  # master switch (the 2nd of two gating levels)
echo 1 > events/sched/sched_wakeup/enable            # one event
echo 'sched:* kmem:*' > set_event                     # by group; wildcards and negation (!event) supported
cat trace                                            # read the buffer (non-consuming; write 1 to trace to clear)
cat trace_pipe                                       # consuming read, no header
echo 1 > buffer_size_kb                              # per-CPU ring size (KiB)
echo 1 > snapshot                                    # stash the current ring; later: cat snapshot

Cost: an unarmed site compiles to one load+test+branch (verified point by point in release disassembly); enabled costs +13–19 ns per record, image cost +0.18%. A disabled call site pays only argument evaluation.

§4debug= runtime switches (the legacy diagnostics surface, frozen)

Boot parameter debug=switch1,switch2 (comma-separated). The authoritative table is debug_switch_table! in kernel/src/debug/switches.rs (67 entries, frozen — new observability goes through the §3 tracepoints); sysrq/debugfs mirror it under /sys/kernel/debug/debug/. The commonly used ones:

Compile-time features (Cargo.toml)

cargo build --target riscv64gc-unknown-none-elf --features riscv64,debug-lock-owner
# debug-lock-owner: one atomic store per lock/unlock; deadlock warnings carry holder=<cpu>

§5Deadlock and hang detection

The three standing defenses

DefenseMechanismCoverage
Compile-time fencetyped lock keys (D-11): once a nesting pair is named in lock-ordering.md it can take keys, and reverse nesting stops compilingmigrated named pairs (GRQ/bucket, waiter-slot/bucket)
Spin watchdogRawSpinlock::DEADLOCK_WARN_ITERS: ~100M spun iterations print a warning; with debug=watchdog an automatic full task snapshot followsdeadlocks that actually spin long enough on a live CPU
SPIN modelskernel/verify/spin/lock_ordering.pml (make spin): deadlock-freedom proofs for the documented pathsthe abstracted paths, at model-check time

lockdep-lite (design accepted, P0 landed)

It closes the uncovered class: an illegal acquisition order on an unkeyed pair down an unmodeled path. It does not copy the reference C shape — static lock-class site declarations plus a runtime graph recording every held-lock nesting edge, cycle-checking each new edge as observed, and splatting with both class names and acquire sites before the deadlock happens. P0 (the static order registry + boot-time validation) is on main; P1/P2 (runtime recording) are in implementation lanes. debug=dlsleep,dlspin are its observation switches.

hunt-wedge: automated capture

./test/hunt-wedge.sh [rounds]   # 6 rounds by default; stops on capture. exit 0=caught, 2=not reproduced

Automatically builds a debug-lock-owner kernel, loops smoke + nettest + pipe-bomb workloads watching for two hang classes (type A: a lock-deadlock warning; type B: a pipe going silent >30 s). On either, it captures per-CPU registers/stacks/disassembly through the QEMU monitor into /tmp/rux-hunt/ and preserves that round's kernel.elf for addr2line. Analysis in three steps: classify the hang from hunt.log → symbolize hunt.dump's pc=/ra= via addr2line -e /tmp/rux-hunt/kernel.elf -f -C → scan stack words for kernel ra values to recover the call chain.

Comparability rules: both sides use the same accelerator (KVM vs KVM); debug vs release-strong never cross-compared; under TCG, p2 readings are host-load-dominated. Census bands: TERM-DESCHED 8±2, WAKE-REFUSED 32±4, ticks ≥99.5/s, no 1001 ms grid class.

§7Memory and filesystem forensics

  • memwatch (debug=): heap/page accounting per call-site — the first tool for leak hunts.
  • allocwatch: cross-CPU lock-holder naming — the waiter cannot self-report (printing allocates, and it is stuck inside the allocator), so the observer names it.
  • mmforensics (debug=): PTE-install ledger, double-teardown detector, page-table stamp rings.
  • TRIMQ (boot param trimq=1): the brk-shrink quarantine — TRIMQ-HIT (who/when/age) + TRIMQ-PRESENT (was the page live at trim) + TRIMQ-FRAME (frame content then-vs-now); the primary instrument of the GNOME heap-corruption investigation.
  • ledger: physical-accounting reconciliation at OOM (zone free/anon/file LRU/dirty — real exhaustion or bookkeeping drift).
  • USEGV-FOR: the user-fault forensic line (cr2 landing, vma hit or not) — how shmat1's test defect was adjudicated.
  • Offline image forensics (no boot): debugfs -R "cat /var/log/kmsg" copied.img; image integrity via e2fsck -f.
  • scribble (debug=): task-control-word scribble hunter; parks on first hit for gdb watchpoints.

§8GDB and QEMU-level debugging

  • GDB: make debug (after make build; attaches to QEMU's gdbstub — breakpoints, single-step, memory inspection).
  • Deterministic reproduction: THREAD=single make run (single-threaded TCG); or ACCEL=tcg to drop KVM.
  • QEMU monitor: attach via a unix socket (the oh-boot.sh shape) — screendump for screens, register/memory dumps (hunt-wedge uses this automatically).
  • Serial to file: -serial file:xxx.log; grep offline after long soaks.
