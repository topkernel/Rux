Tracepoints

kernel/src/trace/ · The unified trace-event system: a single declaration table derives the full event, a byte-exact tracefs, two-level gating and per-CPU rings — design, the complete event inventory and usage · Observability policy (2026-11-02): all new kernel observability enters through this framework

§1Design: one declaration row derives everything

Each event appears exactly once in the tracepoints! declaration table — one row declares the event's full identity: group/name/id/verbatim print fmt/field list/typed call signature/renderer. From that single row the macro derives the three artifacts a hand-written site used to duplicate:

  1. The static table row (group/name/id/print_fmt/fields/enabled) — the table is the catalog;
  2. The record function trace_<name>(field, ...) -> bool — typed arguments pack into argument slots with the armed check inside (when the event is off, the call site pays only argument evaluation);
  3. The renderer <name>_fmt — shared by the text output and the format file.

Design points:

  • The print fmt is captured verbatim from the reference host's live files — the text format and field offsets are byte-identical to the reference, so any host tool (event analyzers parsing the format files) works unmodified.
  • One declaration = one edit: the table row, the call signature and the file shapes are a single edit — the "format and data drift" defect class is structurally unrepresentable (the same derive pattern as procfile! D-4).
  • An argument cap of 10 u64 slots (TRACE_ARGS=10): a comm costs two slots; exceeding it is unrepresentable at compile time (the PackArg trait declares slot usage per type).
  • Two-level gating: recording requires both the event's own enable switch and the global tracing_on; the tracing_on check sits inside record, after argument marshalling.

§3The tracefs tree and usage

Once mounted, the file tree matches the reference file-for-file (standard names, standard modes, byte formats captured from the live host's /sys/kernel/tracing):

mount -t tracefs none /sys/kernel/tracing
cd /sys/kernel/tracing
ls
# tracing_on  trace  trace_pipe  available_tracers  current_tracer
# available_events  set_event  buffer_size_kb  snapshot  options/
# events/<group>/{enable,filter,<event>/{enable,filter,id,format}}

cat events/sched/sched_wakeup/format     # field list + print fmt (byte-exact vs the reference)
cat events/sched/sched_wakeup/id         # the event id

A typical session

echo 1 > tracing_on                                # global master switch (the second gating level)
echo 1 > events/sched/sched_switch/enable          # arm one event
echo 'sched:*' > set_event                          # arm by group (wildcards and negation !event)
echo 'ext4:* jbd2:*' > set_event                    # multiple groups
cat trace                                           # read the buffer (non-consuming; write 1 to trace to clear)
cat trace_pipe                                      # consuming read, no header
echo 4096 > buffer_size_kb                          # per-CPU ring size (KiB)
echo 1 > snapshot                                   # archive the live ring and restart it; read it back with cat snapshot
echo 0 > tracing_on                                 # stop recording (arming retained)

Output line format

%16s-%-7d [%03d] %c%c%c%c%c %5lu.%06lu: %s: %s
#      task      pid  cpu  irq flags     timestamp        group:  content
# e.g. launcher-327  [002] d..1 1234.567890: sched:sched_switch: ...

Rings and consistency

  • Per-CPU rings with per-CPU sequence numbers and read-side timestamp merging — tail latency p99 1.403→0.741 µs (−47%; the observability's own cost is measured).
  • A 600 s fully-armed soak survived 1.56M ring overwrites with zero panics — the ring-full overwrite path is verified.

§4Mapping the legacy dfx= switches to events

The old ad-hoc switch table is frozen (see the debugging guide); its instrumentation migrated into trace events, and the boot parameter dfx=<name> is now an alias arming the corresponding event family:

dfx= aliasrux: events armed
dfx=taskdumprux:taskdump (periodic task snapshots)
dfx=watchdogspinlock warnings + rux:taskdump linkage
dfx=memwatchrux:memwatch (allocation-site accounting)
dfx=mmforensicsrux:mmforensics (PTE ledger/double-teardown detection)
dfx=schedtracerux:schedtrace (scheduler stepping)
dfx=sysringrux:sysring (syscall dual-recording)
dfx=sigtracerux:sigtrace (signal chains)
dfx=ohhuntrux:ohhunt (drm ioctl/mmap/prime-import)
dfx=fuxstuck / txnhang / spinwatch / hilogcensusthe corresponding rux: events (hunt-specific observation points)

The complete retired-token table and the mapping implementation live in kernel/src/dfx/switches.rs (the trace alias table); /sys/kernel/debug/dfx/ mirrors the same control surface in debugfs.

§5How to add an event

  1. Add one row to the tracepoints! table in kernel/src/trace/mod.rs: group/name/id/print fmt (captured verbatim from the reference's live files, or self-declared for the rux: family)/field list/call signature/renderer.
  2. Call trace_<name>(args...) at the site — no hand-written armed checks, packing or rendering.
  3. Guest-side verification: cat events/<group>/<name>/format must be byte-identical to the reference format (reference families), or self-consistent with the declaration (rux: family).
  4. Cost verification: confirm one-load call sites in the release disassembly; a two-arm microbenchmark for the enabled cost.

Policy basis: the observability policy (2026-11-02) — the old dfx= ad-hoc switch table is frozen at 49 entries and must not grow; any new observation point must enter this framework as a tracepoint. This is an interface decision aligned with the reference (the debugfs/tracefs ecosystem works directly), not an internal preference.
