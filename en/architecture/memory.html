Memory management

From memblock to vmemmap, buddy, small_alloc and the page cache — source: docs/architecture/memory.md + the mm/ sources

§1Address-space layout

The virtual-layout constants match the reference item by item, keeping userspace ELF loaders and the /proc view compatible. Sv39 (riscv64) as the example:

§2The three-stage boot

memblock → fixmap → zone/buddy: memblock maintains memory + reserved dual-region tables (128-region cap); page-table pages go through three stages (static BSS EARLY_PMD×8/EARLY_PTE×128 → memblock → zone). The allocator-off world is strictly separated from the allocator-on world.

§3Page descriptors and buddy

  • vmemmap: one 64-byte cache-line-aligned Page per physical page (flags/mapcount/refcount/private/mapping/index/type/next_free); pfn↔page O(1). Refcount semantics: fork shares +1, a COW write fault +2; freeing only at 0.
  • zone/buddy: MAX_ORDER=10 (4 MB blocks max), free lists on Page.next_free, release merges via buddy_pfn = pfn ^ (1<<order); Unmovable/Movable/Reclaimable migrate types.
  • PCP (per-CPU pageset): order-0 allocations take the per-CPU fast path with zero zone locks; high/batch watermarks refill in batches.
  • kswapd / OOM: woken at WMARK_HIGH; 16 consecutive failed passes trigger the OOM killer; LRU lists + referenced rotation + rmap + compaction (two-pointer scan + migration).

§4The three-tier kernel heap

kmalloc
  ├─ ≤1024 B  → small_alloc (a SLUB-style packed small-object layer)
  ├─ 8..4096  → slab.rs (ten classes, separate path)
  └─ >4 KB    → buddy (standalone, orders 0–20)

small_alloc: the magazine cache

  • 8 power-of-two classes (8..1024B); 16-byte slab-page headers (magic 0x5142), FIRST_OFF(S)=max(16,S) for object alignment.
  • Per-CPU magazine (depth 16): alloc/free hit the magazine; class locks are taken only for batched refill/flush — the source of the "class-lock sections ≤25M/boot" gate row (measured 19.7M, latest board 6.0M).
  • Free-bit routing + sentinel: one bit per slab page routes frees; the bit is cleared before the page returns — a stale pointer lands on the buddy-side sentinel rather than corrupting silently.
  • Lock order: class lock → buddy lock.
  • Origin: OH's first frame left ~213k live 1B–1KB objects (23.2M allocs/23.0M frees), each pinning a 4KiB buddy block = 852MB of a 992MB window — the allocator died during first-frame composition, and the magazine was built for it.

The packed kernel-stack slab (divergence D-2, x86_64)

Three kernel stacks packed per 256KB order-6 block (80KB slots) + a slot side table + empty-block recycling: 85.3KB/stack vs 128KB (saving ~115MB where stacks were 42% of a 904MB budget), 99.9% slot packing, deepest recorded 3,445 live tasks with zero canary hits. Non-gated architectures compile it out (the 80KB slack is an x86_64 measurement).

§5Page cache

  • Key: ((fs_id, inode), page_index) — without fs_id pages cross file systems.
  • Lock model (pcache option B): lockless global slot-table reads (reader-bank SeqCst RMW + Acquire slot probes) + per-inode spinlocks; wlock only inserts/evicts; whole-slot removal goes tombstone + wait for banks to drain before drop.
  • Capacity: floor 8,192 pages (32MB), soft cap half of managed RAM. The old fixed 32MB cap made OH library loads cost ~1.5 s per fault (SA:3002 OpenSo 802166ms).
  • Window batch fill (divergence D-12): one round trip fills the whole miss window (demand + sequential readahead, or a 16-page fault-around cluster); contiguous physical segments merge into single multi-block requests (bio::bread_async_multi, ≤64 blocks/128KiB); the consistency guard cuts the run at the first cached block (DMA must not bypass live dirty buffers).

§6Deferral and concurrency control

  • The deferred-free ring (D-16): MmStruct/Task free into a 16,384-slot global ring drained on a 1500 ms wall clock — bounded reclamation latency independent of scheduling (QSBR RCU cannot see procfs walkers' unaccounted borrows, hence the wall clock).
  • Per-mm PTE locks (INV-LOCK-7, uniform across archs): a global epoch (RwSpinlock reads) + per-mm spinlock split mode, replacing the global PTE lock that let fork-walks monopolize the machine.
  • Leaf-table direct unmap: ownership makes the per-page walker allocation-free; the upper chain resolves once per 2MiB block and iterates leaf PTEs directly. Measured: mmap avg 72 µs→27–32 µs (max 749 ms→2.1–3 ms), munmap body 177–185→52 µs, >16MiB mmap median 5.6 ms→415–427 µs; OH workload vm-op family ~15 s→~5 s/CPU-min.
  • Anon reclaim (SP-7): reclaim check rate 35%→82–89%, swap writes +75%.

§8Historical lessons (taxonomy excerpts)

  • buddy split not marking allocated → the same block handed out twice (016b3fa1).
  • vmscan refcount<=0 underflow arm double-free; page_cache double-invalidation double-put (f4b67f66, R14-16) — two instances of the "typed Refcount" gap.
  • The first CpuLocal landed in a non-mut static → LLVM placed it in .rodata → at opt≥1 every store was deleted (15.9M objects / 2 lock holds of silent catastrophe); the UnsafeCell re-landing verified the stores in disassembly.
  • copy_kernel_mappings copied a kernel L1 entry pointing at a user L0 → execve overwrote the parent's PTEs (7a497838).
  • The munmap chunked rework lost the tail TLB flush (fixed in c4a548d7; caught within hours by the OH battery — the synthetic probe was structurally blind because it read back the same stale state).
