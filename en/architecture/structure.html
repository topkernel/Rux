§2Layering and unsafe governance

docs/architecture/kernel-layers.md defines the longest-prefix-match layering: unmatched files default into the safest bucket.

  • The consolidation campaign (collected 2026-11-27; per-statement narrowing + safe-function repatriation 2026-11-28) landed: the whole repo's unsafe lives in 18 audited per-subsystem unsafe.rs files plus tests/, per-statement granularity with every block under an INV contract; the other 401 files carry file-level forbid(unsafe_code).
  • The machine gate: scripts/gate_unsafe_mainline.py is green repo-wide (rc=0) — zero unsafe outside the audited files; new unsafe is a compile error.
  • The syscall boundary: entries validate and translate user pointers in one place; uaccess_safe.rs provides typed copy_in/copy_out (INV-UACCESS-1).
  • The dual-series total is 0.99% of the kernel (3,936 of 397,552 physical lines: 1,329 blocks / 3,661 lines + 165 fn-impl items / 275 lines; 6,396 regions before the campaign).

The probe-tarball policy: guest test-case sources are archived only as userspace/probes/probes.tar.gz + extract.sh; make user / make test restore them idempotently via scripts/extract-probes.sh — loose guest C sources are never committed.

§4Language composition

The kernel itself is 100% Rust (no_std, plus the necessary platform assembly); userspace probes are C (musl cross-compiled); repository language statistics use the git ls-files basis (vendored toybox is marked linguist-vendored).
