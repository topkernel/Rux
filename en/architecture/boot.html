Boot flow

Firmware handshake to init, per architecture — source: docs/architecture/boot.md and the arch/ sources

§1riscv64

QEMU -kernel rux
  └─ OpenSBI (fw_dynamic)   M-mode
       └─ S-mode _start      a0=hartid, a1=DTB, other harts parked
            ├─ early stvec, tp (per-CPU area), Sv39 kernel page table
            └─ boot hart initializes every subsystem → others wfi for SMP_INIT_DONE
  • SBI calls used: PUT_CHAR / SHUTDOWN / HART_START (0x48534D) / SEND_IPI (0x735049).
  • Timer: the Sstc extension writes stimecmp directly (no per-tick SBI ecall).

§2x86_64 (q35)

multiboot1 ELF → 64-bit stub → rust_main
  └─ SIPI trampoline wakes the APs
       ├─ bzImage boot protocol: the same image boots on loaders expecting it
       └─ the bootstrap PML4's low identity window is UNLINKed right after the
          boot-stack switch (divergence D-17)

§3aarch64 (QEMU virt)

QEMU -M virt,gic-version=3 -kernel rux   # bare ELF, no boot protocol
  └─ a complete QEMU-virt DTB blob embedded (exported by build.rs)
       ├─ EL2 → EL1h: HCR_EL2=RW, interrupts routed to EL1, both timers enabled,
       │  CPACR_EL1.FPEN
       └─ the early TTBR0 identity window (phys [0,2GB)) is torn down after SMP starts
aarch64 requires -M virt,gic-version=3; the cmdline comes from the embedded DTB's /chosen/bootargs.

§4Serial markers of a successful boot

Minimal system: the OpenSBI banner → the Rux ASCII banner → the module init table (console/trap/mm/sched/fs/driver/smp all [ok]) → init: loading /bin/sh → the shell prompt.

x86_64 Ubuntu: init complete → framebuffer resolution → login screen ready; boot-to-login ~4.5 s on 4 vCPUs MTTCG.

§5Boot parameters and image discipline

  • A typical kernel cmdline: root=/dev/vda rw init=/sbin/init console=ttyS0 (+ optional debug= flags, effective on riscv64/x86_64; not available on aarch64 because the EL2 trampoline destroys the DTB pointer before cmdline parsing — compile-time features instead).
  • Shared images boot only with -snapshot + file.locking=off; never hand-write QEMU commands for standard flows — the parameters live in the Makefile and the existing driver scripts.
