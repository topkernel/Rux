The Micro-core: a Type-Isolated Kernel

kernel/rux-core + service crates · the one criterion, the irreducible floor, the three-layer defense, and the flip ladder — every mechanism with measured data · Design of record: docs/architecture/micro-core-design.md

§1The fundamental difference from Linux: one criterion, two halves

The essential difference between Rux and Linux is not any one subsystem's algorithm — it is how the trusted computing base (TCB) is defined. Linux is a ~28-million-line C monolith: the type system does not check memory safety, so the entire kernel is the TCB — any pointer error anywhere can corrupt anything; isolation is attempted through code review and runtime hardening.

Rux turns the same property into a compile-time structure via the Rust type system. The criterion is a single question asked of every line:

Can this code live under #![forbid(unsafe_code)]?
YES → it belongs in a service crate (compiler-guaranteed zero unsafe). NO → it belongs in rux-core (under an INV contract or F-row, covered by the verification stack). There is no third bucket.

Corollary: the service subsystems (syscalls, networking, filesystem leaf layers, drivers, ext4, and the policy layers of scheduling and memory management) become structurally unable to express memory unsafety once their crates carry crate-level forbid — wild pointers, use-after-free, and data races, the classes that dominate the C-kernel CVE history, are structurally zero in the service columns. This is not "careful coding"; it is a compiler guarantee: the only way to add unsafe to a forbid crate is to delete the crate attribute itself, and the CI ratchet makes that deletion an explicit, reviewable act.

§3The three-layer defense: 0 + ~50 + 0 cycles

Microkernels (seL4/L4 family) buy fault isolation with a separate address space per service, at ~1,000 cycles per cross-service IPC on the best fastpaths, multiplied along fault→driver→server chains (the Mach lesson). Rux replaces address-space isolation with language isolation, plus a hardware backstop — three layers, each at its measured cost point:

LayerMechanismBoundary cost (measured)What it buys
Typeforbid crates + the Cargo dependency graph (Cargo refuses cycles = one-way deps machine-checked)0 (cross-crate calls, LTO-inlined; the flip verified zero behavior change)Service columns cannot express memory unsafety at compile time
HardwareIntel MPK protection keys: page-grain hardware domains inside the one address space47–49 cycles/window (100k TSC-timed ops; an address-space switch is ~1,000+)Core metadata pages tagged; out-of-window access takes a hardware #PF (fault-injection proven); the <1% budget holds
VerificationKani 12/12 all-input proofs + Miri zero-UB + Verus narrow-adopt (unbounded arithmetic lemmas)0 (offline)The core's ~3,000 hand-written unsafe lines are machine-checked

In one line: a microkernel spends ~1,000 cycles per boundary to buy the first layer; Rux buys all three for 0 + ~50 + 0, at finer grain (MPK to the page; IPC only to the process). The mpkguard framework has landed (default off, enabled by mpkguard=1): the vring AVAIL sections are the phase-1 target (measured ~2.4k windows/s).

§4End-state topology and the flip ladder

rux-core          (≈3,000 lines; the entire TCB)
  entry/switch/uaccess/page-table asm · safety/ · sync primitives · task lifecycle · timer core
  ← covered by Kani/Miri/Verus

rux-sched-policy  forbid safe (CFS/RT/fairness/wakeup policy — decisions out of the core)
rux-mm-policy     forbid safe (VMA tree / mmap / COW / fault decisions)
rux-syscall       forbid safe (41k lines, 12 files — the flip is DONE)
rux-fs-svc · rux-ext4 · rux-net · rux-drivers · rux-ipc · rux-dfx-svc

Scheduling and memory management do not become whole crates: both are decidable policy riding a small unsafe core — after the split the policy layer is forbid-safe and the core stays in rux-core. The switch/tp/lock primitives/page-table atomics are TCB; CFS mathematics is not. Each rung's binding order: measure the reverse surface → design the seam → flip → forbid → the domain battery (the sched split passes the P4 storm + context-switch benchmarks; the mm split the mmap/fault families). A rung whose measurement shows a non-decomposable surface is shelved with its numbers recorded — shelving is success, not failure.
