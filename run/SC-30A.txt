DESIGN (implemented, commit c3e5a314 "fix(fs): scoped publication draining"):

Root mechanism (confirms 29A adjudication, one addition): THREE stacked
world-drains sat under every fsync/fdatasync — ext4_sync_file step 1
(flush_publications), the forced jbd2 commit (flush_publications at
jbd2_journal_commit_transaction entry), and the tail bio::sync_buffers (its own
flush_publications + sync_all whole-cache write). mkdir added a fourth
(namei.rs post-mkdir sync_buffers). The drain loop ("loop: a racing publisher
may have appended") has NO exit bound — under sustained create churn an fsync
loops until creators pause, which is the 43-min hiview draw; the 1.2-1.4 s
accesstoken WAL syncs are single drains of a large queue.

Fix shape — ordering enforced at the granularity of what each point WRITES:
- Publication records carry cookie = publishing task address.
- flush_publications_scoped() (fsync/fdatasync entry, mkdir publication point):
  publishes the caller's OWN records in full (pre -> entry -> post, per device)
  plus a minimal cross-record obligation closure (H1: any pending record whose
  entry block is in the plan contributes its pres; H2: any pending record whose
  post block is in the plan contributes its entry, which pulls its own H1 set).
  Foreign records stay pending; foreign POSTS are never written by us. A task
  with no pending records (the hiview case): one queue scan, zero I/O.
- flush_publication_constraints(mj,mi,blk) (sync_dirty_buffer guard, evict_one
  guard): H1/H2 closure for the ONE block about to be written.
- flush_publications() whole-queue unchanged for the true global points
  (sync(2)/syncfs/sync_file_range/shutdown).
- jbd2 commit: whole-drain REMOVED — every fs block the commit writes goes
  through sync_dirty_buffer, which is now per-block guarded.
- ext4_sync_file: tail sync_buffers REMOVED; added an explicit sync of the
  file's own inode-table block (new inode::inode_table_block_of) — covers the
  no-handle O_TRUNC size-update case that used to ride the tail. Data blocks
  and the forced commit unchanged.
- mkdir: post-mkdir sync_buffers -> flush_publications_scoped (its own record
  only; the r8 mkdtemp ENXIO shape dies too — foreign devices never touched).
- Queue bound: PUB_HIGH_WATER=2048 records -> producer-paid bounded drain
  (2 batches) inside publication_defer — backlog reclamation is paid by the
  creator, bounded, and leftover records stay ordered.
- fsw=1 counters: FSW1 gains ps=<scoped>.<own records> pc=<constraint flushes>
  ph=<hiwat drains> pm=<queue max>. No new dfx= switch (SWITCH_COUNT stays 37).

Safety argument (documented in bio.rs block comment): the contract is per
record pre->entry->post plus H1/H2 for every block written; the scoped flush
satisfies both for everything IT writes. The pre-existing cross-record window
(shared cumulative metadata block written "at first mention" can persist a
later record's free before its entry removal) is the SAME class the
append-order whole drain always had — no new window class introduced.
Pre-existing race kept as-is (noted for a future fix): a global sync(2) whose
flush sees an empty queue while a scoped flush holds records in its I/O
snapshot can then hash-order-write constrained blocks — identical window
existed with two concurrent whole drains; not worsened.

PROCESS MISHAP (lesson for me): my first oh-boot-30a.sh launch via setsid
appeared dead at +20 s because the 4G scgold cp had not finished — it was
alive and grabbed HDC 12221; my explicit retry then failed ON THAT port and
I re-ran with 12232, whose script rm -f'd + re-copied the SAME userdata path
under the first boot (truncating its guest storage). Killed the stray pair
(own-PID discipline); the surviving serial log belongs to the 12232 boot
only (the stray qemu wrote to a deleted inode — no interleaving). LESSON:
wait for the userdata cp (or use per-tag userdata paths) before declaring a
launch dead; the serial log only appears after the cp.
