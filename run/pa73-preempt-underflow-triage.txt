1. WHAT THE PRINTS ACTUALLY ARE
===============================
Every cluster in the stress lane's own r17 logs (read-only,
ltp-fix-b/.ltp/logs-r17/) is the heal's DOCUMENTED guard-unpair report,
in the exact shape their session-3 verdict already banked ("the 18 sub=0x1
reports are the documented guard-unpair path (healed 10 s spinlock holds,
drop-site named)"):

  PREEMPT-HEAL cpu=0 pid=0x1d9 was=0x10001 held_jiffies=0x3f0
  PREEMPT-UNDERFLOW pid=0x1d9 count_was=0 sub=1 ... spinlock.rs:461 lock=<static>

- was=0x10001 = base 1 (ONE live/leaked PREEMPT bit) + the tick's own
  in-flight HARDIRQ_OFFSET at the heal sample (sched.rs round-3c heal).
- held ~0x3e8-0x3f2 jiffies = the heal fires at its >=1000-jiffy (10 s)
  threshold, i.e. the observed hold is ~10.08 s — the wedge duration.
- The underflow is the AFTERMATH: the heal (timer IRQ) cleared the base
  bit while a SpinlockGuard was live; that guard's drop then books -1 on
  the zeroed count. Clamp-to-0; no corruption; LTP rows byte-identical
  with/without any of this (their own A/B: 25-file failure set equal).
- Locks VARY across clusters: static PROCESS_TREE_LOCK (waitid rows) AND
  heap Spinlocks (0xffffffd609xxxxxx, cgroup_core rows, pids 0x14e/0x151/
  0x155/0x156/0x15f). Not one lock's bug — a mechanism.

3. WHY THE S12 ATTRIBUTION FAILED
=================================
- Their control (fleet r11/r12 zero) is a stochastic miss: the same
  pre-delta kernel family produced r64/r65 = ZERO and r66 = 142 heals in
  adjacent rounds; the wedge is load/timing dependent.
- The kernel delta 488528dc..979fde80 contains NO preempt-count-semantics
  change: exit.rs/sched.rs/signal.rs deltas are tracepoint marshalling
  behind armed(); trap.rs adds a lock-free per-tick PC stash; perf/mod.rs
  is new but gated; timer.rs adds one relaxed load. The behavioral
  changes are D-7 small_alloc, virtio input IRQ delivery, posix_mq
  deadline, madvise, pipe abort plumbing — none touch preempt_count.
- D-7 SPECIFICALLY is exonerated by mechanism: CpuLocal::with manipulates
  ONLY the IRQ flag (save_and_disable_irq/restore_irq) and a per-row
  in_use flag; it never adds or subtracts preempt_count. The small_alloc
  conversion kept the identical irq windows and fallbacks (diff-verified).
  The stress lane's "per-CPU preempt-count carrier" description of D-7
  does not match the code — there is no preempt-count carrier in it.
