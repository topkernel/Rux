scanner fragility, mm-race flake):

- OH musl rwlock protocol VERIFIED from ld-musl-x86_64.so.1 disassembly:
  word = low31 reader count | bit31 WAITERS; writer holds at 0x7fffffff;
  readers BARGE (CAS val+1) regardless of WAITERS; readers park only at
  writer-held (expect 0xffffffff); WRITERS park expecting word|WAITERS —
  so the frozen 0x80000010 parkers are writers, and reader-unlock emits
  NO kernel traffic except the last-out wake(1). The kernel futex layer
  cannot leak the count; only dead/parked holders can.
- abilityMapLock_ is NOT a musl rwlock: samgr binary imports
  ffrt_rwlock_* (SAMGR_USE_FFRT); ffrt SharedMutexPrivate = fast_mutex +
  2 waiter lists + state (writeEntered bit31 | readers). Its waits park
  on PER-THREAD condvars, never on the shared word. So the frozen word
  belongs to some OTHER musl pthread_rwlock in the samgr process.
  DEFAULT_WORK_THREAD_NUM = 16 in ipc_process_skeleton.h — the "16
  readers" matches the libipc worker pool cap; park stacks will name the
  exact lock (sc84/sc85 boots carry the adoption-time dump).
